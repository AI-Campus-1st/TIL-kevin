# 서비스 정의서: 남성 입문 스타일링 (가칭)

## 0. 문서 정보
- 상태: 1차 기준본 (미결 사항 1차 결정 반영)
- 작성일: 2026-10-13
- 근거 문서: [plan1_idea.md](plan1_idea.md) (아이디어 원안과 Claude 피드백 1, 2차)
- 표기 규칙
  - `[확정]`: 결정된 사항. 변경 시 이 문서부터 수정
  - `[제안]`: 검토 결과 권장안. 채택 전까지 변경 가능
  - `[미정]`: 결정 필요. 11장 미결 사항 ID(Q-n)와 연결
- 서비스 운영 전제 `[확정]`
  - 기획자 본인이 첫 사용자로 직접 사용할 서비스
  - 수익 구조는 고려하지 않음. 편의성과 만족도에만 집중

## 1. 한 줄 정의
- `[확정]` 사복을 입어 본 적 없는 20~30대 남성이 상황, 예산, 키, 몸무게와 쉬운 질문 몇 개에 답하면 어울리는 헤어스타일과 옷을 함께 추천받고, 미용실에 전달할 문구와 구매 목록, 스타일 유지 관리 방법까지 안내받는 서비스

### 엘리베이터 피치 `[제안]`
교복, 군복, 근무복만 입다가 갑자기 꾸며야 하는 남자를 위한 첫 스타일링
어려운 용어를 몰라도, 쇼핑몰을 뒤지지 않아도 질문 몇 개에 답하면 미용실에서 할 말, 살 옷, 매일 유지하는 법까지 알려 드림

## 2. Problem
### 2.1 문제 정의 `[확정]`
| 구분 | 내용 |
|---|---|
| 판단 문제 | 자신에게 무엇이 어울리는지 모름 |
| 실행 문제 | 옷 이름, 헤어 용어를 몰라 검색, 구매, 미용실 요청을 못 함 |
| 유지 문제 | 한 번 꾸며도 매일 같은 모양으로 재현하고 관리하는 법을 모름 |

- 공통 제약: 패션을 공부할 의지와 경험이 부족하며 누군가 알아서 정해 주길 원함

### 2.2 현재 대안과 한계
| 현재 대안 | 한계 |
|---|---|
| 미용실에서 "알아서 해 주세요" | 결과가 미용사에 따라 다름, 손질법을 모르면 다음 날 재현 불가 |
| 친구, 가족에게 질문 | 상대의 취향과 지식에 의존 |
| 유튜브 코디 영상, 마네킹 착장 구매 | 본인 체형, 얼굴과 무관한 일반론 |
| ChatGPT 등 범용 LLM | 질문을 잘 해야 함, 결과가 일반론 수준이고 실행 단계가 구조화되어 있지 않음 |

### 2.3 근거 `[미정]`
- 현재는 기획자 본인 경험 기반. 기획자 본인 사용 결과를 1차 근거로 활용 (9장)

## 3. Target
### 3.1 타깃 정의 `[확정]`
- 20~30대 남자
- 옷 종류나 헤어스타일에 무지함
- 고등학교, 군대, 직장 등에서 정해진 옷만 입고 살아서 사복을 입을 기회가 없었음
- 대충 살아서 그동안 꾸민 적이 없음
- 소개팅, 면접 등 외관을 꾸며야 하는 상황이 발생함
- 자기관리를 위해 외관을 신경 쓰기 시작함
- 잘 모르니 일단 저렴하게 세팅하려고 함

### 3.2 타깃의 핵심 축
- 나이가 아닌 '사복 경험 부족'이 공통 축
- 보유 사복이 거의 없는 상태에서 시작한다는 전제

### 3.3 사용 계기 유형 `[제안]`
| 유형 | 예시 | 니즈 | 서비스 내 역할 |
|---|---|---|---|
| 이벤트형 | 소개팅, 면접 | 기한 있음, 일회성. 빠르게 완성된 한 벌 | 첫 사용 계기 |
| 자기관리형 | 외관 관리 시작 | 지속적. 기본 옷장 구성과 반복 가능한 관리법 | 지속 사용 계기 |

- 이벤트형으로 처음 사용하고 자기관리형으로 이어지도록 구성해 일회성 사용 완화

## 4. Solution
### 4.1 핵심 가치 `[확정]`
- 헤어스타일과 옷을 함께 추천
- 추천한 헤어를 미용실에 그대로 전달할 문구 제공
- 추천한 옷을 예산 안에서 바로 살 수 있는 구매 목록 제공
- 추천한 스타일을 유지하는 관리 방법까지 안내
- 사용자는 용어나 패션 지식 없이 따라가기만 하면 됨

### 4.2 산출물 `[확정]`
| 산출물 | 내용 |
|---|---|
| 헤어 추천 | 어울리는 헤어스타일과 선택 이유 |
| 미용실 주문서 | "미용실에 이렇게 말씀하세요" 문구와 함께 출력하는 시술 요청 내용. 예: "투블럭, 옆머리 6mm, 윗머리 가위컷, 다운펌" |
| 옷 추천 | 선택한 복장 유형에 맞춘 착장 세트 (상의, 하의, 신발 등) |
| 구매 목록 | 품목별 상품명, 추천 사이즈, 가격, 구매 링크, 합계 금액. 합계는 선택한 예산 구간 이내 |
| 관리 가이드 | 헤어 손질법(드라이 방향, 왁스 양 등), 커트 주기, 옷 관리법 |

### 4.3 사용자 흐름
| 단계 | 내용 | 상태 |
|---|---|---|
| 1. 상황 선택 | 소개팅, 면접, 출근, 일상(자기관리) 등 | `[제안]` |
| 2. 복장 유형 선택 | 캐주얼, 비즈니스 캐주얼, 정장 중 선택. 상황별 권장 유형을 안내해 결정 유도 (예: 면접 선택 시 "대부분의 면접에는 정장 또는 비즈니스 캐주얼이 적합") | `[확정]` |
| 3. 예산 선택 | 10만 원 단위 가격대 구간 중 선택 | `[확정]` |
| 4. 신체 수치 입력 | 키, 몸무게 | `[확정]` |
| 5. 주관 기준 질문 | 얼굴, 모질, 체형 (5장) | `[확정]` |
| 6. 제약 조건 | 거부 항목(펌, 염색 등), 아침 손질 가능 시간 | `[제안]` |
| 7. 결과 | 헤어 추천과 미용실 주문서, 옷 추천과 구매 목록 | `[확정]` |
| 8. 관리 가이드 | 헤어 손질, 커트 주기, 옷 관리 | `[확정]` |

## 5. 입력 설계
### 5.1 입력 항목
| 항목 | 방식 | 상태 |
|---|---|---|
| 상황 | 선택형 | `[제안]` |
| 복장 유형 | 선택형 (캐주얼, 비즈니스 캐주얼, 정장) | `[확정]` |
| 예산 | 10만 원 단위 구간 선택 | `[확정]` |
| 키, 몸무게 | 수치 입력 | `[확정]` |
| 얼굴형, 체형 | 사용자 주관 기준 질문 | `[확정]` |
| 모질 | 사용자 주관 기준 질문 | `[제안]` |
| 거부 항목, 손질 시간 | 선택형 | `[제안]` |
| 사진 + LLM 비전 분석 | 보류. 확장 여지만 확보 (5.3) | `[확정]` |

### 5.2 주관 기준 질문 설계 원칙 `[제안]`
- 용어 대신 경험으로 질문
  - 얼굴: "얼굴이 길다는 말을 들어 본 적 있나요?", "턱이 각진 편인가요?"
  - 모질: "곱슬인가요?", "아침에 옆머리가 뜨나요?", "숱이 많은 편인가요?"
  - 체형: "셔츠를 입으면 어깨가 꽉 끼나요?", "배가 나온 편인가요?"
- 선택지는 글보다 그림 위주
- "모르겠음" 선택지 제공, 이 경우 키, 몸무게 기반 기본값 적용
- 모질 항목 포함 이유: 남성 헤어 추천은 얼굴형보다 모질(다운펌 필요 여부 등)의 영향이 클 가능성
- 체형 질문 포함 이유: 키, 몸무게가 같아도 어깨, 복부, 다리 비율 차이를 구분하지 못함

### 5.3 사진 + LLM 경로 확장 여지 `[확정]`
- 현 단계: 기술적 난도를 고려해 보류. 주관 기준 응답에만 의존
- 확장 여지 확보를 위한 설계 제약
  - 얼굴, 모질, 체형 항목은 고정된 선택지 값으로 저장 (자유 텍스트 금지)
  - 추천 로직은 '입력 경로'가 아닌 '선택지 값'만 참조
  - 향후 사진 분석은 같은 선택지 값 중 하나를 출력하는 모듈로 추가. 추천 로직 수정 불필요
- 향후 도입 시 검토 사항: 호출당 비용, 결과 일관성, 사진 품질 의존, 사진 업로드 거부감, 개인정보 동의와 보관 정책

## 6. 추천 및 생성 방식 `[제안]`
- 스타일 결정: 미리 정한 스타일 목록(헤어 N종, 복장 유형별 옷 조합 N종) 안에서 입력값 기반 규칙으로 선택
  - 이유: 결과 일관성 확보, 상품 연결 용이, 추천 품질 검수 가능
- 사이즈 추천: 키, 몸무게와 체형 응답 기반
- LLM 역할: 다음 용도로 한정
  - 선택된 스타일의 쉬운 말 설명, 관리 가이드, 미용실 주문서 문장 생성
  - 사용자 후속 질문 응답 (예: "왁스 대신 뭘 써도 되나요?")
- 스타일 목록의 출처와 갱신 주체: `[미정]` Q-6
- 구매 목록용 상품 데이터 확보 방식: `[미정]` Q-10

## 7. 차별화
### 7.1 경쟁 지형 요약
| 유형 | 대표 서비스 | 미커버 영역 |
|---|---|---|
| 헤어 추천/시뮬레이션 | HairMe, 헤어트라이, YouCam Makeup, CutMuse | 옷, 체형, 관리법 |
| 옷장/코디 앱 | 에이클로젯, Style DNA, Alta | 헤어. 보유 옷 등록 전제, 여성 중심 |
| 커머스 AI | 무신사(카카오톡, ChatGPT 앱), 에이블리 AI | 체형, 얼굴형, 헤어 |
| 사람 스타일리스트 | 크몽, 숨고 퍼스널쇼퍼 | 2시간 8~15만 원 수준, 헤어 별도 |
| 범용 LLM | ChatGPT, Gemini | 구조화된 실행 단계, 일관성 |

- 남성 대상 헤어와 옷을 한 번에 추천하는 전용 서비스는 조사 시점(2026-10) 기준 미발견
- 실질적 경쟁자는 무료 범용 LLM
- 상세 내용: [plan1_idea.md](plan1_idea.md) "경쟁 서비스 검토"

### 7.2 차별점
| 차별점 | 경쟁 대비 근거 | 상태 |
|---|---|---|
| 헤어와 옷의 통합 추천 | 기존 서비스는 헤어 또는 옷 한쪽만 다룸 | `[확정]` |
| 미용실 주문서 | 시술 지시 수준 출력은 경쟁 서비스에서 미확인 | `[확정]` |
| 예산 내 구매 목록 | 헤어 앱, 옷장 앱은 구매까지 연결하지 않음. 커머스 AI는 체형, 헤어 미반영 | `[확정]` |
| 관리 방법 안내 | 기존 서비스는 추천, 미리보기에서 종료 | `[확정]` |
| 용어 없는 입력 | 기존 서비스는 사진 업로드 또는 용어 기반 선택 | `[확정]` |
| 사복 0벌에서 시작 | 옷장 앱은 보유 옷 등록이 전제 | `[확정]` |
| 상황 단위 추천 | 무신사 TPO 추천은 헤어, 체형 미반영 | `[제안]` |

- 얼굴형, 체형 분석 자체는 차별점이 아님 (헤어 앱, 옷장 앱에서 이미 일반화)
- 범용 LLM 대비 존재 이유: 질문 역량 없이도 일관되고 구조화된 결과물(추천, 주문서, 구매 목록, 관리 가이드)을 받는 점

## 8. 범위 `[확정]`
| 구분 | 항목 |
|---|---|
| 포함 | 헤어 추천, 미용실 주문서, 옷 추천(캐주얼, 비즈니스 캐주얼, 정장), 구매 목록, 관리 가이드 |
| 제외 | 안경, 눈썹, 피부 관리 / 수익 구조 / 사진 + LLM 분석(현 단계, 확장 여지만 확보) / 여성 대상 / 보유 옷 등록 기반 옷장 관리 |

## 9. 핵심 가정과 검증
| ID | 가정 | 검증 방법 `[제안]` |
|---|---|---|
| A-1 | 키, 몸무게와 주관 기준 응답만으로 어울리는 스타일을 '얼추' 맞출 수 있음 | 기획자 본인 및 주변 타깃 대상 추천 후 만족도 확인 |
| A-2 | 사용자가 추천 결과를 실제로 실행함 (커트, 구매) | 추천 후 1~2주 내 실행 여부 확인 |
| A-3 | "미용실에 이렇게 말씀하세요" 문구만으로 의도한 헤어가 나옴 | 실제 시술 결과와 추천 이미지 비교 |
| A-4 | 관리 가이드가 있으면 다음 날 이후에도 스타일을 재현함 | 일주일 후 재현 여부 확인 |
| A-5 | 키, 몸무게, 체형 응답 기반 사이즈 추천이 맞음 | 구매 후 교환, 반품 여부 확인 |

### 성공 지표 `[제안]`
- 편의성: 입력 시작부터 결과 확인까지 소요 시간, 이탈 단계
- 만족도: 추천 결과 만족도, 실제 시술 결과 만족도, 착용 만족도
- 실행률: 추천 후 실제 커트, 구매 비율
- 정확도: 사이즈 교환, 반품 비율

| 주문서 전달 실패 | 미용실마다 용어 해석이 다를 수 있음 | 문구와 함께 참고 이미지 제공 검토 |
| 상품 정보 노후화 | 가격 변동, 품절, 링크 만료 | 상품 데이터 갱신 방식 결정 (Q-10) |
| 사이즈 오차 | 브랜드마다 사이즈 기준이 다름 | 브랜드별 실측 기준 반영 검토 |
| 일회성 사용 | 이벤트 후 이탈 | 자기관리형 전환, 커트 주기 알림 |
