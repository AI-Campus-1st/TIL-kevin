# 아이디어 제안

### 두루뭉술한 생각
- 밖에 잘 안 나가고 사람 잘 안 만나서 어떻게 꾸며야할 지 모르겠다
- 꾸며볼려고 해도 나한테 어울리는 게 뭔지도 모르겠고 옷 이름, 헤어스타일 종류도 모르다보니 손 놓게 됨
- 아무렇게나 상관없으니 아무나 나를 알아서 꾸며줬으면 좋겠다
- 일반적이고 정형화된 스타일링이 있으니 얼굴형, 체형을 알면 얼추 맞출 수 있지 않을까?

### PTS 구조화
- Problem: 패션을 모르고 공부해야할 게 많아서 스타일링이 어려움
- Target: 20~30대 남자
  - 옷 종류나 헤어스타일에 무지함
  - 고등학교나 군대, 직장 등에서 정해진 옷만 입고 살아서 사복을 입을 기회가 없었음
  - 대충 살아서 그동안 꾸민 적이 없음
  - 소개팅, 면접 등 외관을 꾸며야 하는 상황이 발생함
  - 자기관리를 위해 외관을 신경 쓰기 시작함
  - 잘 모르니 일단 저렴하게 세팅하려고 함
- Solution: 헤어스타일과 옷을 함께 추천하고, 스타일을 유지하는 관리 방법까지 안내

### 차별화
- 얼굴형, 체형을 입력받아 어울리는 스타일 추천
- 복잡한 설명 없이 따라가기만 하면 완성됨
- 패션에 대해 공부할 필요가 없음

### 엘리베이터 피치

꾸미는 법을 모르는 남자들을 위한 종합 스타일링 서비스
어려운 용어 공부할 필요 없이, 쇼핑몰 뒤져볼 필요 없이 그저 하라는 대로만 하면 스타일링 완성!

- 실질적 경쟁자는 무료 범용 LLM(ChatGPT, Gemini)

#### 기존 차별화 항목 재검토
| 항목 | 판정 | 근거 |
|---|---|---|
| 얼굴형, 체형 입력 후 추천 | 차별점 아님 | 얼굴형은 헤어 앱 대부분, 체형은 에이클로젯, Style DNA에서 이미 제공 |
| 복잡한 설명 없이 따라가기만 하면 완성 | 차별점 후보 | 기존 앱은 추천, 미리보기에서 종료. 단 '따라가기'의 구체적 정의 부재 |
| 패션 공부 불필요 | 위 항목과 중복 | 무신사 대화형 추천도 동일 가치 표방 |

- 현재 차별화는 입력(무엇을 분석하나)에 집중되어 있으나 이 영역은 이미 일반화된 상태
- 차별점은 출력(분석 결과를 실제 행동으로 바꾸는 단계)에서 확보 필요

#### 차별화 기회 (경쟁 서비스 공백)
- 헤어와 옷의 통합 룩
  - 얼굴형, 체형, 헤어 분위기와 옷 스타일이 일관된 하나의 완성 룩 제시
  - 현재는 헤어 앱과 코디 앱을 따로 써야 하고 상호 일관성 없음
- 미용실 주문서 (가장 강력한 후보)
  - 타깃의 실제 문제는 용어를 몰라 미용실에서 원하는 바를 전달하지 못하는 것
  - 예: "투블럭, 옆머리 6mm, 윗머리 가위컷, 다운펌" 형태의 카드를 미용사에게 그대로 제시
  - 기존 헤어 앱은 합성 이미지에서 종료, 시술 지시 수준의 출력은 미확인
- 옷이 없는 상태에서 시작
  - 옷장 앱은 보유 옷 등록이 전제이나 타깃은 보유 옷이 적고 등록 의욕도 낮음
  - 장바구니 한 번에 구매 가능한 기본 세트(상의, 하의, 신발, 사이즈 포함) 제공이 타깃에 적합
- '꾸며야 할 일' 단위 추천
  - Target 정의("꾸며야 할 일이 있는")의 기능화
  - 소개팅, 면접, 결혼식 하객, 첫 출근 등 이벤트 선택 시 헤어와 옷 동시 추천
  - 무신사 TPO 추천에는 헤어, 체형 미반영
- 유지 방법 안내
  - 커트 후 집에서 같은 모양을 재현하는 방법(드라이 방향, 왁스 양 등) 제공
  - '하라는 대로만 하면'의 마지막 단계이며 경쟁 서비스에서 미확인

#### 리스크 및 보완 필요 사항
- 범용 LLM 대비 존재 이유: "ChatGPT에 사진 올리면 되지 않나?"에 대한 답 필요. 미용실 주문서, 상품과 사이즈 연결 같은 정형화된 실행 산출물이 답이 될 수 있음
- '얼추 맞출 수 있다' 전제 검증: 남성 헤어는 얼굴형보다 모질(곱슬, 숱, 직모)과 두상, 옷은 체형보다 사이즈 핏의 영향이 클 가능성. 입력 항목 재검토 필요. 체형 분석 앱들도 첫 진단을 확정이 아닌 출발점으로 취급
- 일회성 사용: 한 번 꾸미고 이탈할 가능성 높음. 이벤트별 재방문, 커트 주기 알림 등 재사용 구조 필요
- 대형 플랫폼 진입: 무신사가 대화형 AI 추천을 빠르게 확장 중. 체형, 헤어 기능 추가 시 데이터와 상품 우위로 밀릴 가능성
- 얼굴 사진 개인정보: 민감정보 처리 방침 필요

### 기타 지적사항

#### 우선 보완 순서
1. 입력 방식과 타깃의 모순 해소 (Solution 항목 참고) -> 2차 피드백에서 방향 결정
2. '추천'과 '완성' 사이의 간극을 메우는 Solution 재정의 -> 관리 방법 안내까지가 목표 Solution으로 명확화
3. 핵심 가정 목록과 검증 계획 추가
4. 수익 구조, 획득 채널 정의

#### Problem
- 하나의 문장에 성격이 다른 문제가 섞여 있음. 두루뭉술한 생각에서 드러난 문제는 최소 세 가지
  - 판단 문제: 무엇이 어울리는지 모름
  - 실행 문제: 옷 이름, 헤어 용어를 몰라 검색, 주문, 전달을 못 함
  - 의욕 문제: 신경 쓰기 귀찮고 누가 대신 해 주길 원함 ("아무나 나를 알아서 꾸며줬으면")
- 현재 Problem("공부해야 할 게 많아서")은 판단 문제만 다루고 있음. 실행 문제와 의욕 문제가 오히려 차별화 근거(미용실 주문서, 따라가기만 하면 완성)와 직결되므로 Problem에 명시 필요
- 문제의 빈도와 심각도 근거 부재. 본인 경험 외에 같은 문제를 겪는 사람이 얼마나 되는지, 얼마나 불편한지에 대한 근거(인터뷰, 커뮤니티 글 등) 필요
- 현재 대안(workaround) 분석 부재. 타깃이 지금 실제로 하는 행동 정리 필요
  - 미용실에서 "알아서 해 주세요"라고 맡기기
  - 친구, 가족에게 물어보기
  - 유튜브 남자 코디 영상, 마네킹 착장 그대로 구매
  - 이 대안들이 왜 불충분한지가 곧 이 서비스의 존재 이유

#### Target
- 범위가 너무 넓음. 연령, 상황, 예산이 없음
  - 20대 초반 대학생, 20대 후반 취준생, 30대 직장인은 예산, 원하는 스타일, 꾸밀 상황이 모두 다름
  - 초기 집중 타깃(beachhead) 한정 필요. 예: "소개팅이나 면접을 앞둔 20대 중후반 남성"
- 두루뭉술한 생각("밖에 잘 안 나가고 사람 잘 안 만나서")과 Target("꾸며야 할 일이 있는")의 연결 고리가 암묵적임. 평소에는 니즈가 없다가 특정 이벤트가 생길 때 니즈가 생긴다는 점을 명시하면 사용 시점과 획득 시점이 함께 정의됨
- 지불 의사 낮은 타깃. 패션에 관심 없는 사람은 스타일링에 돈을 쓸 동기도 약함. 누가, 무엇에 돈을 내는지 별도 정의 필요 (정의서에 빠진 항목 참고)

#### Solution
- 입력 방식과 타깃의 모순 (가장 중요)
  - 차별화에 "얼굴형, 체형을 입력받아"라고 되어 있으나 타깃은 자기 얼굴형, 체형을 모르는 사람
  - 사용자가 직접 고르는 방식이면 그 단계에서 이탈하거나 잘못 입력할 가능성이 높음
  - 사진 기반 자동 판별 또는 "어깨가 넓은 편인가요?" 같은 쉬운 질문으로 대체 필요
- '추천'과 '완성'의 간극
  - Solution은 "추천"인데 엘리베이터 피치는 "하라는 대로만 하면 완성"
  - 추천을 받은 뒤 미용실 예약, 시술 요청, 상품 검색, 사이즈 선택, 매일 손질은 여전히 사용자 몫
  - Solution을 '추천'이 아닌 산출물 중심으로 재정의 필요. 예: 미용실 주문서, 구매 목록, 손질 가이드
- 사용자 플로우 부재. 첫 화면부터 결과물을 받기까지의 단계와 소요 시간, 입력 항목 수가 정의되어 있지 않음
- 최소한의 사용자 제약 조건 미반영
  - "아무렇게나 상관없다"는 생각과 달리 실제로는 거부 조건이 존재함. 예: 펌, 염색 거부, 예산 상한, 회사 복장 규정, 아침 손질 시간
  - 이를 무시한 추천은 실행되지 않을 가능성이 높으므로 2~3개 수준의 제약 질문 필요
- 스타일 범위 미정의
  - 남성의 인상 변화에는 헤어, 옷 외에 안경테, 눈썹 정리, 피부 관리 영향도 큼
  - MVP에서 제외하더라도 범위 밖으로 둔다는 결정 자체를 명시 필요
- 추천 규칙의 출처와 갱신 주체 부재
  - "일반적이고 정형화된 스타일링"의 근거가 무엇인지(스타일리스트 자문, 기존 가이드, LLM 생성 등) 미정의
  - 트렌드 변화 시 누가 규칙과 상품 목록을 갱신하는지 미정의
- 품질 보증과 피드백 루프 부재
  - "알아서 해 달라"는 사용자는 결과가 실패하면 서비스 탓을 하고 이탈함
  - 결과 사진 업로드, 만족도 평가 등 추천 품질을 확인하고 개선하는 장치 필요

#### 엘리베이터 피치
- Solution에 없는 약속이 포함됨. "쇼핑몰 뒤져볼 필요 없이"는 상품 연결을 전제로 하지만 Solution, 차별화 어디에도 쇼핑 연결이 없음. 둘 중 하나로 일치 필요
- "종합 스타일링 서비스"는 무엇을 받는지가 드러나지 않는 추상적 표현. 사용자가 손에 쥐는 결과물(주문서, 구매 목록 등)을 직접 언급하는 편이 전달력이 높음
- "꾸미는 법을 모르는 남자들"이라는 호칭을 타깃이 자기 얘기로 받아들일지 확인 필요. 결핍을 지적하는 표현보다 상황("소개팅 전날", "면접 앞두고")을 짚는 표현이 거부감이 적을 가능성

#### 정의서에 빠진 항목
- 핵심 가정 목록. 틀리면 아이디어 전체가 무너지는 가정 정리 필요
  - 얼굴형, 체형만으로 '얼추' 어울리는 스타일을 맞출 수 있음
  - 타깃이 추천 결과를 실제로 그대로 실행함 (커트, 구매)
  - 꾸밀 일이 생겼을 때 타깃이 이 서비스를 찾아옴
- 검증 계획. 위 가정을 개발 전에 확인할 방법 필요. 예: 타깃 5~10명 인터뷰, 수작업으로 주문서와 구매 목록을 만들어 주고 실제 실행 여부 관찰
- 수익 구조
  - 타깃의 지불 의사가 낮으므로 사용자 과금보다 커머스 제휴 수수료, 미용실 예약 수수료 등 간접 수익이 현실적일 가능성
  - 어떤 방식이든 Solution 설계(상품 연결 여부 등)에 영향을 주므로 초기 정의 필요
- 획득 채널
  - 패션에 관심 없는 사람은 패션 앱, 패션 콘텐츠를 보지 않음
  - "소개팅 옷", "면접 머리" 같은 이벤트 직전 검색 시점이 사실상 유일한 접점일 가능성. 이 시점에 어떻게 노출될지 정의 필요
- 성공 지표. 무엇을 보면 성공인지 미정의. 예: 추천 후 실제 커트 또는 구매 비율, 이벤트 후 만족도, 재방문율

#### 표기, 형식
- 맞춤법
  - "꾸며야할 지" -> "꾸며야 할지"
  - "꾸며볼려고" -> "꾸며보려고"
  - "모르다보니" -> "모르다 보니"
  - "공부해야할" -> "공부해야 할"
- 제목 단계가 `#` 다음 바로 `###`로 넘어가 `##`가 생략됨. 문서 구조상 `##` 사용 권장
- PTS 항목은 한 줄씩이라 판단 근거가 드러나지 않음. Problem과 Target에는 근거(경험, 관찰, 수치)를 한두 줄 덧붙이는 편이 설득력 있음

### 2차 피드백

#### 반영 내역
- Target: 20~30대, 사복 경험 부족, 꾸밀 상황 발생, 저렴한 세팅 지향으로 구체화
- Solution: 추천에 더해 스타일 유지 관리 방법 안내까지 포함
- 입력: 키, 몸무게는 수치 입력으로 확정. 얼굴형, 체형은 주관적 기준 또는 LLM 활용 중 검토
- 차별화의 "얼굴형, 체형을 입력받아" 문구는 입력 방식 확정 후 수정 필요

#### 얼굴형, 체형 입력 방식 검토
| 방식 | 장점 | 단점 |
|---|---|---|
| 주관적 기준 질문 | 사진 부담 없음, 구현 단순, 비용 없음, 결과 일관성 높음 | 자기 인식 오차 존재. 용어형 질문("얼굴형이 무엇인가요?")은 타깃이 답하지 못함 |
| 사진 + LLM(비전) 분석 | 사용자 판단 불필요. 모질, 숱, 이마, 어깨 비율처럼 사용자가 말로 설명 못 하는 요소까지 파악 가능 | 호출당 비용, 같은 사진에도 답이 달라지는 일관성 문제, 사진 품질 의존, 얼굴, 전신 사진 업로드에 대한 거부감, 개인정보 동의와 보관 정책 필요 |
| 혼합 (권장) | 기본은 질문, 원하는 사용자만 사진으로 보정. 진입 장벽 낮고 정확도 보완 가능 | 두 경로 모두 구현해야 함 |

- 주관적 기준 질문 설계 원칙
  - 용어 대신 경험으로 질문. 예: "얼굴이 길다는 말을 들어 본 적 있나요?", "셔츠를 입으면 어깨가 꽉 끼나요?", "아침에 옆머리가 뜨나요?"
  - 선택지는 글 대신 그림 위주
  - "모르겠음" 선택지를 두고 키, 몸무게 기반 기본값으로 처리
- 질문에 포함할 항목
  - 얼굴: 길이(긴 편, 보통, 짧은 편), 턱선(각진 편, 둥근 편), 이마 넓이
  - 모질: 곱슬 여부, 숱, 옆머리 뜸 여부. 남성 헤어 추천은 얼굴형보다 이 항목의 영향이 클 가능성이 높음 (다운펌 필요 여부 등)
  - 체형: 어깨 넓이, 배 나옴 여부, 다리 길이 체감. 키, 몸무게만으로는 같은 수치라도 체형 차이를 구분하지 못함
- LLM 활용 위치 제안
  - 스타일 선택 자체를 LLM에 맡기면 매번 결과가 달라지고 상품과 연결하기 어려움
  - 스타일 선택은 미리 정한 스타일 목록(헤어 N종, 옷 조합 N종) 안에서 규칙 기반으로 결정하고, LLM은 다음 용도에 한정하는 편이 안정적
    - 선택된 스타일을 쉬운 말로 풀어 쓴 설명, 미용실 주문서, 관리 가이드 생성
    - 사용자 후속 질문 응답 (예: "왁스 대신 뭘 써도 되나요?")
    - 사진 보정 경로에서 얼굴, 체형 항목 판별 (위 질문 항목과 같은 선택지 중 하나를 고르도록 제한)

#### 구체화된 Target 검토
- 개선점
  - 사복 경험 부족이라는 배경, 소개팅과 면접이라는 계기, 저렴한 세팅이라는 예산 성향이 드러나 이전보다 훨씬 명확함
  - 20~30대로 폭은 넓지만 공통 축이 나이가 아닌 '사복 경험 부족'이라 타깃의 일관성은 유지됨
- 계기 두 가지의 니즈 차이
  - 이벤트형(소개팅, 면접): 기한이 있고 일회성. 빠르게 완성된 한 벌이 필요함
  - 자기관리형: 지속적. 기본 옷장 구성과 매일 반복할 관리 방법이 필요함
  - 관리 방법 안내라는 목표 Solution은 자기관리형과 더 잘 맞음
  - 이벤트형으로 유입시키고 자기관리형으로 계속 쓰게 만드는 구조로 연결 가능. 앞선 지적의 일회성 사용 리스크에 대한 답이 될 수 있음
- 면접 복장의 범위
  - 면접은 정장이나 비즈니스 캐주얼이 필요해 소개팅용 캐주얼과 다른 카테고리임
  - 정장까지 다룰지, 캐주얼만 다룰지 범위 결정 필요
- "저렴하게 세팅"의 구체화
  - 예산 상한을 입력받을지, 서비스가 정해 둔 예산 구간을 제시할지 결정 필요
  - 옷: 기본 아이템 위주이므로 SPA, 가성비 브랜드 중심 구성이 자연스러움
  - 헤어: 저가 미용실, 바버샵에서도 가능한 스타일 위주. 펌, 염색이 필요한 스타일은 추가 비용을 함께 안내
  - 관리: 왁스, 드라이기 등 관리 도구 비용도 초기 세팅 비용에 포함 필요
- 수익 구조와의 충돌
  - 저렴한 세팅 지향 타깃은 사용자 과금 의사도 낮고, 저가 상품은 커머스 제휴 수수료 규모도 작음
  - 수익 구조 정의 시 이 점을 고려 필요

#### 목표 Solution 관련
- "추천 + 관리 방법 안내"로 목표가 명확해짐
- 다만 추천과 관리 사이의 실행 단계(미용실에서 요청하기, 상품 구매, 사이즈 선택)는 여전히 사용자 몫으로 남아 있음
- 타깃이 '용어를 모른다'는 점을 고려하면 이 단계에서 이탈할 가능성이 가장 높으므로, 미용실 주문서와 구매 목록을 Solution에 포함할지 결정 필요
