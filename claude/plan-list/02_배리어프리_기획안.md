# [기획안 02] 서울 지하철 교통약자 엘리베이터 동선 및 출구-목적지 무장애 보행 안내 서비스

> 개발 조건: 수업 실습 프로젝트, 무료 공개 데이터만 사용, 서울 한정, 카카오맵 API 확보, 백엔드 Python FastAPI

## 1. 개요 및 목적
- **프로젝트명**: 서울 지하철 교통약자 엘리베이터 동선 및 출구-목적지 무장애 보행 안내 서비스
- **추진 배경**
  - 휠체어 이용자, 고령자, 유모차 이용자는 지하철 이용 시 엘리베이터가 있는 출구와 역 안 동선을 미리 알아야 함
  - 서울시는 2025년 말 서울 지하철 전 역사에 지상부터 승강장까지 이어지는 엘리베이터 동선 설치 완료를 발표함 → "엘리베이터가 있는 역 찾기"보다 "어느 출구 엘리베이터로 나가서 목적지까지 어떻게 가는지"가 핵심 정보
  - 엘리베이터가 있는 출구에서 목적지까지의 지상 구간에도 육교·지하보도 같은 장애 요소 존재
- **목적**
  - 역별 교통약자 시설과 엘리베이터 출구 위치를 지도에 표시
  - 엘리베이터 출구에서 목적지까지 육교·지하보도를 피하는 보행 경로 제공
- **범위**
  - 서울교통공사 운영 노선(1~8호선) 우선. 9호선·신분당선·코레일 구간은 "데이터 미제공" 표시
  - 지하철 노선 간 경로 탐색(어느 노선을 탈지)은 범위 밖. 단일 역의 출입 동선과 지상 보행 구간에 집중

## 2. 주요 기능 정의
1. **역 검색 및 교통약자 시설 상세**
   - 역 선택 시 엘리베이터, 휠체어리프트, 장애인화장실, 휠체어 급속충전기 보유 현황 표시
2. **엘리베이터 출구 지도**
   - 지상 엘리베이터 위치를 출구 번호와 함께 CustomOverlay로 표시
3. **가동 정보 표시 (기준일 명시)**
   - 승강기 가동현황 데이터를 "YYYY-MM-DD 기준 정상 / 점검"으로 표시
   - 실시간 정보가 아님을 화면에 명시
4. **출구-목적지 무장애 보행 경로**
   - 목적지 입력 시 가장 가까운 정상 가동 엘리베이터 출구를 출발점으로 선택
   - 도보 네트워크에서 육교·지하보도 링크를 제외하고, 신호 있는 횡단보도를 우선하는 경로를 Polyline으로 표시
5. **역 안 이동 단계 안내**
   - 시설 위치 설명 정보를 이용하여 "지상 엘리베이터 → 대합실 → 승강장 엘리베이터" 순서를 텍스트로 안내
   - 2D 지도에 역 안 동선을 그리지 않음 (실내·층별 동선은 평면 지도 표현 부적합)
6. **사용자 제보**
   - 엘리베이터 고장, 지상 구간 단차·경사 제보 폼
   - 관리자 확인 후 지도에 "제보 있음" 표시

- **확인 필요 사항**
  - 승강기 가동현황 CSV의 최근 갱신 여부 (공공데이터포털 메타데이터상 수정일 2023-08)
  - 교통약자이용정보의 위치 설명 필드 구성 (역 안 단계 안내 가능 여부)
  - 도보 네트워크 유형 코드에서 육교·지하보도·계단 구분 여부
  - 엘리베이터 위치정보와 교통약자이용정보 간 역·시설 식별자 연결 방법

## 4. 시스템 아키텍처 및 기술 스택
- **Frontend**
  - HTML5, CSS3, JavaScript (ES6+)
  - Kakao Maps JavaScript SDK (Marker, CustomOverlay, Polyline, services 라이브러리)
  - 접근성: 큰 글씨 모드, 색상과 텍스트 병기, 화면 낭독기용 대체 텍스트
- **Backend**
  - Python FastAPI (역·시설 조회, 보행 경로 탐색, 제보 등록 API)
  - SQLite (가동현황 기준일 데이터, 사용자 제보 저장)
- **Data Processing**
  - Pandas (시설·가동현황 정제, 역 식별자 매칭)
  - GeoPandas, NetworkX (도보 네트워크 그래프, 육교·지하보도 제외 경로 탐색)
  - PyProj (좌표계가 WGS84가 아닌 데이터가 있을 경우 변환)

## 5. 개발 워크플로우 및 단계별 실행 계획

```
[1단계: 요구사항 정의 및 API 확보]
  └─ 공공데이터포털·서울 열린데이터광장 인증키 발급, 카카오 도메인 등록
  └─ FastAPI 기초 실습 (라우팅, 쿼리 파라미터, CORS 설정)
  └─ 대상 노선 확정 (서울교통공사 1~8호선 중 시범 노선 1~2개)

[2단계: 데이터 정제 및 매칭]
  └─ 엘리베이터 위치정보, 교통약자이용정보, 가동현황을 역명·시설 기준으로 매칭
  └─ 역명 표기 차이 정리 (예: "서울역" / "서울역(1호선)")
  └─ 좌표계 확인 및 WGS84 통일

[3단계: 보행 경로 그래프 구축]
  └─ 시범 노선 역 주변 반경 1km 도보 네트워크 추출
  └─ 육교·지하보도 링크 제외, 신호 횡단보도 링크 가중치 감산

[4단계: 백엔드 API 및 DB 구현]
  └─ 역 목록·역 상세, 엘리베이터 출구, 보행 경로, 제보 등록·조회 엔드포인트
  └─ 가동현황 CSV 정기 갱신 스크립트 (일 1회)

[5단계: 프론트엔드 카카오맵 연동]
  └─ 엘리베이터 출구 CustomOverlay, 경로 Polyline, 역 안 단계 안내 UI
  └─ 접근성 모드 (큰 글씨, 고대비)

[6단계: 테스트 및 검증]
  └─ 시범 역 5곳의 엘리베이터 위치를 카카오맵 출구 위치·현장 사진과 대조
  └─ 보행 경로에 육교·지하보도 링크가 포함되지 않는지 자동 검사
  └─ 가동 상태 표시는 점검 상태가 포함된 테스트 데이터로 화면 예외 처리 확인
```

## 6. 기대 효과 및 확장 가능성
- **기대 효과**
  - 엘리베이터 출구 확인과 출구 이후 지상 구간 장애 요소 회피를 한 화면에서 해결
  - 사용자 제보로 공공 데이터의 갱신 공백 보완
- **한계**
  - 가동 정보는 일 단위 기준일 정보로, 당일 고장 미반영
  - 2020년 기준 도보 네트워크로 단차·경사 정보 부재 → 제보로 점진 보완
- **향후 확장성**
  - 서울교통공사 외 운영기관 노선 데이터 추가
  - 저상버스 정류장·도착 정보 연동
  - 누적 제보 데이터를 자치구·운영기관 피드백 자료로 정리
