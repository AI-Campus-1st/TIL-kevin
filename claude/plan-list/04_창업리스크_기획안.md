# [기획안 04] 서울 공공 상권·인허가 데이터 기반 창업 업종 생존 리스크 진단 대시보드

> 개발 조건: 수업 실습 프로젝트, 무료 공개 데이터만 사용, 서울 한정, 카카오맵 API 확보, 백엔드 Python FastAPI

## 1. 개요
- **프로젝트명**: 서울 공공 상권·인허가 데이터 기반 창업 업종 생존 리스크 진단 대시보드
- **추진 배경**: 예비 창업자가 업종·상권을 고를 때 "이 상권에서 이 업종이 얼마나 오래 살아남았는지"를 근거 있게 비교할 도구 필요
- **목적**: 인허가 데이터의 개업·폐업일자로 상권·업종별 생존 곡선을 계산하고, 매출·인구·경쟁·임대료 지표와 결합한 리스크 점수를 과거 데이터로 검증하여 제공
- **타겟 사용자**: 서울 예비 창업자
- **범위**
  - 대상 지역: 서울특별시
  - 대상 업종: 인허가 데이터로 개·폐업 추적이 가능한 업종 (일반음식점, 휴게음식점, 제과점영업, 미용업, 세탁업 등)
  - 영업 중 소상공인 대상 마케팅 분석은 범위 밖
- **기존 서비스와의 차별점**
  - 소상공인 상권정보시스템·서울시 상권분석서비스(웹)는 현황 통계 중심
  - 본 서비스는 상권·업종별 생존 곡선과 백테스트로 검증한 리스크 점수 제공

## 2. 주요 기능
1. **상권 리스크 지도**: 업종 선택 시 상권 영역 Polygon을 리스크 등급(5단계) 색상으로 표시 (단계구분도)
2. **상권 상세 대시보드**
   - 분기별 점포 수, 개·폐업 수 추이
   - 업종 추정매출 추이 (최근 8개 분기)
   - 시간대별 생활인구·길단위인구 차트
3. **업종 생존 곡선**
   - 선택 상권과 서울 전체의 Kaplan-Meier 생존 곡선 비교
   - 1년·3년 생존율 수치 표시
4. **리스크 점수 리포트**: 구성 요소별 점수와 근거 데이터, 기준 분기 표시
5. **입지 후보 비교**
   - 입력: 업종, 월 임대료 상한, 선호 자치구(선택)
   - 출력: 리스크 점수 상위 5개 상권 비교 표
   - 임대료 정보가 없는 상권은 "임대료 정보 없음"으로 표시하고 필터에서 제외하지 않음

## 3. 활용 데이터 및 API
| 데이터 | 제공처 | 주요 정보 | 갱신 | 활용 목적 |
| :--- | :--- | :--- | :--- | :--- |
| 지방행정 인허가 데이터 (서울분) | LOCALDATA | 업종, 인허가일자, 폐업일자, 영업 상태, 좌표 | 일 단위 | 생존 분석 핵심 데이터 |
| 서울시 상권분석서비스 (영역) | 서울 열린데이터광장 | 상권 영역 경계, 상권코드, 상권 유형 | 비정기 | 분석 단위, 지도 Polygon |
| 서울시 상권분석서비스 (점포·추정매출·길단위인구) | 서울 열린데이터광장 | 상권·업종별 점포 수, 개·폐업 수, 추정매출, 시간대별 유동인구 | 분기 | 경쟁·매출·인구 지표 |
| 서울 생활인구 (행정동) | 서울 열린데이터광장 | 시간대·성별·연령대별 생활인구 | 일 단위 | 상권 배후 인구 |
| 소상공인 상가(상권)정보 (서울분) | 공공데이터포털 | 업소 위치, 업종 | 분기 | 경쟁 점포 (인허가 외 업종 포함) |
| 상업용부동산 임대동향조사 | 한국부동산원 R-ONE (Open API) | 주요 상권별 ㎡당 임대료, 공실률 | 분기 | 임대료 부담 지표 |
| 카카오맵 API | Kakao Maps JavaScript SDK | 지도, Polygon, Marker | | 상권 지도 |
| Chart.js | | | | 추이·생존 곡선 차트 |

- **용어 구분**: 생활인구(특정 시점 그 지역에 있는 인구, 거주자 포함)와 유동인구(통행량)를 구분하여 사용. 상권 단위 통행량은 상권분석서비스 길단위인구 사용
- **확인 필요 사항**
  - LOCALDATA 좌표의 좌표계 (중부원점 TM 계열, EPSG 코드 확인)
  - 부동산원 상권 구분과 서울시 상권분석서비스 상권 영역의 대응 관계 (상권명 기준 수동 매핑 필요)
  - R-ONE Open API 인증키 발급 절차와 호출 방식

## 4. 리스크 점수 설계
- **구성 요소** (상권 × 업종 단위)

| 요소 | 산출 방법 | 방향 |
| :--- | :--- | :--- |
| 생존 | 3년 생존율 (Kaplan-Meier) | 낮을수록 위험 |
| 경쟁 강도 | 동종 점포 수 ÷ 길단위인구 | 높을수록 위험 |
| 매출 추세 | 최근 4개 분기 추정매출 증감률 | 감소할수록 위험 |
| 폐업 추세 | 최근 4개 분기 폐업률 | 높을수록 위험 |
| 임대료 부담 | ㎡당 임대료 (제공 상권만) | 높을수록 위험, 미제공 시 제외하고 가중치 재배분 |

- **정규화와 합산**: 요소별 서울 전체 백분위로 변환 후 가중 합산, 5단계 등급화
- **표본 부족 처리**: 상권·업종 표본(인허가 건수)이 30건 미만이면 자치구 단위 생존율로 대체하고 "표본 부족" 표시
- **폐업과 이전 구분**: 폐업 후 90일 이내, 반경 1km 이내에 같은 상호로 같은 업종 인허가가 새로 나면 "이전"으로 추정하여 폐업에서 제외
- **아직 영업 중인 업소**: 생존 분석에서 중도절단(관측 종료)으로 처리

## 5. 시스템 아키텍처 및 기술 스택
- **Frontend**
  - HTML5, CSS3, JavaScript (ES6+)
  - Kakao Maps JavaScript SDK (Polygon, Marker, CustomOverlay)
  - Chart.js (추이 차트, 생존 곡선)
- **Backend**
  - Python FastAPI (상권 목록, 상권·업종 지표, 생존 곡선, 후보 비교 API)
  - SQLite (사전 계산한 지표·생존 곡선 테이블)
- **Data Processing**
  - Pandas, NumPy (데이터 병합, 지표 계산)
  - GeoPandas, PyProj (좌표계 변환, 점포-상권 영역 공간 결합)
  - lifelines (Kaplan-Meier 생존 분석)
  - SciPy (백테스트 순위 상관)

## 6. 개발 단계별 워크플로우

```
[1단계: 요구사항 정의 및 데이터 소스 식별]
  └─ 서울 열린데이터광장·공공데이터포털·R-ONE 인증키 발급, 카카오 도메인 등록
  └─ FastAPI 기초 실습
  └─ 대상 업종 3~5개 확정

[2단계: 데이터 확보 및 공간 정합]
  └─ 인허가·상권분석서비스·생활인구·상가정보 서울분 다운로드
  └─ 상권 영역 Polygon WGS84 변환
  └─ 인허가 좌표 TM → WGS84 변환, 상권 영역 point-in-polygon으로 상권코드 부여
  └─ 생활인구(행정동)는 상권 영역과 행정동의 겹친 면적 비율로 배분
  └─ 부동산원 상권 ↔ 서울시 상권 수동 매핑표 작성

[3단계: 생존 분석 및 지표 계산]
  └─ 인허가 데이터로 업소별 영업 기간 계산 (영업 중 = 중도절단)
  └─ 이전 추정 규칙 적용, 상권·업종별 Kaplan-Meier 생존 곡선 산출
  └─ 경쟁·매출·폐업·임대료 지표 계산, 백분위 정규화, 리스크 점수 산출

[4단계: 백테스트]
  └─ 기준 시점(예: 3년 전)의 데이터만으로 리스크 점수 산출
  └─ 이후 3년 실제 생존율과 순위 상관(스피어만) 계산
  └─ 상관이 낮으면 가중치 조정, 최종 가중치와 백테스트 결과를 리포트에 공개

[5단계: 백엔드 API 구축]
  └─ 사전 계산 테이블을 SQLite에 저장, 조회 엔드포인트 구현

[6단계: 프론트엔드 및 대시보드 연동]
  └─ 상권 Polygon 단계구분도, 상세 대시보드, 생존 곡선, 후보 비교 표

[7단계: 통합 테스트 및 검증]
  └─ 생존율 계산 결과를 상권 2~3곳 수기 계산과 대조
  └─ 표본 부족 상권 처리, 임대료 미제공 상권 처리 확인
  └─ 대시보드 응답 속도 확인
```

## 7. 기대 효과 및 한계
- **기대 효과**
  - 상권·업종별 실제 생존 기록에 근거한 창업 리스크 비교
  - 백테스트 결과 공개로 점수의 신뢰 범위 제시
- **한계**
  - 인허가 대상이 아닌 업종(일반 소매 등)은 생존 분석 불가
  - 상호 기준 이전 추정은 오분류 가능
  - 임대료는 부동산원 조사 상권에 한해 제공
  - 과거 생존율이 미래 생존을 보장하지 않음
