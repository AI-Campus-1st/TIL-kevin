# [기획안 06] 익명 조건 입력 기반 맞춤 공공 혜택 추천 서비스

> 개발 조건: 수업 실습 프로젝트, 무료 공개 데이터만 사용, 서울 한정, 카카오맵 API 확보, 백엔드 Python FastAPI

## 1. 개요
- **프로젝트명**: 익명 조건 입력 기반 맞춤 공공 혜택 추천 서비스
- **추진 배경**
  - 중앙부처·서울시·자치구의 지원 사업은 수가 많고 지원 조건이 서로 달라, 개인이 받을 수 있는 혜택을 스스로 찾기 어려움
  - 정부24 보조금24 등 기존 맞춤 조회 서비스는 로그인과 본인 인증이 필요하여 "가볍게 확인해 보기"에 부담
  - 이사, 취업, 결혼, 출산 같은 생활 변화에 따라 새로 받을 수 있는 혜택을 미리 알기 어려움
- **목적**: 로그인 없이 연령·가구·소득 구간 등 조건을 입력하면, 받을 수 있는 공공 혜택을 충족 근거와 함께 제시하고 신청 준비까지 안내
- **타겟 사용자**: 서울 거주 성인 (특히 청년, 신혼부부, 영유아 가구, 1인 가구)
- **범위**
  - 대상 혜택: 중앙부처 소관 전국 대상 서비스 + 서울시 + 서울 25개 자치구 소관 서비스
  - 신청 대행은 하지 않고, 신청 경로·서류·기관 안내까지만 제공
- **기존 서비스와의 차별점**
  - 로그인·본인 인증 없이 익명 조건 입력, 매칭을 브라우저에서 수행하여 개인 조건이 서버로 전송되지 않음
  - 조건별 충족 근거 표시와 "이 조건만 확인하면 받을 수 있음" 안내
  - 생활 변화 시뮬레이션으로 앞으로 받을 수 있는 혜택 미리 보기

## 2. 주요 기능
1. **조건 입력 마법사**
   - 단계형 입력: 기본 정보(나이, 성별, 거주 자치구) → 가구(가구원 수, 혼인, 자녀 연령) → 경제(월 소득 구간, 주거 형태) → 상태(취업·학업) → 관심 분야
   - 모든 항목 "선택 안 함" 허용. 입력하지 않은 조건은 "확인 필요"로 처리
   - 장애, 보훈, 한부모 등 특수 조건은 기본 미입력, 사용자가 원할 때만 펼쳐서 입력
2. **맞춤 혜택 목록**
   - 결과를 "받을 수 있음", "확인 필요", "해당 없음" 세 그룹으로 표시
   - 혜택마다 조건별 충족 여부 표시 (예: 연령 충족, 소득 구간 충족, 무주택 여부 확인 필요)
   - 정렬: 신청 마감 임박순, 관심 분야 일치순
3. **혜택 상세 및 신청 체크리스트**
   - 지원 내용, 신청 방법, 신청 기간, 구비 서류, 문의처
   - 구비 서류를 체크리스트로 만들어 준비 상태 표시
4. **생활 변화 시뮬레이션**
   - "이사", "취업", "결혼", "출산", "나이 +1년" 등 변화를 선택하면 조건을 바꾸어 다시 매칭
   - 새로 받을 수 있게 되는 혜택과 받을 수 없게 되는 혜택을 비교 표시
5. **관심 혜택 저장 및 마감 캘린더**
   - 관심 혜택을 브라우저에 저장, 신청 마감 일정을 달력으로 표시
   - 캘린더 파일(.ics) 내보내기로 개인 캘린더 앱에 일정 추가
6. **신청 기관 지도**
   - 방문 신청 혜택은 접수 기관(주민센터, 구청 등) 위치를 카카오맵에 표시
   - 사용자 거주 자치구 기준 가장 가까운 주민센터 안내

- **확인 필요 사항**
  - 공공서비스(혜택) 정보 API의 지원 조건 응답 필드 구성 (연령 범위, 성별, 소득 구간, 가구·직업 유형 등이 코드 형태로 제공되는지)
  - 서비스 상세의 소관 기관 필드로 서울시·서울 자치구 서비스를 구분할 수 있는지
  - 온통청년 API 인증키 발급 절차와 공공서비스 API와의 중복 정도

## 4. 추천 로직 설계
- **조건 정규화 (서버, 데이터 수집 시 1회)**
  - 혜택별 지원 조건을 내부 조건 스키마로 변환

| 조건 항목 | 내부 표현 | 예시 |
| :--- | :--- | :--- |
| 연령 | 최소·최대 나이 | 만 19~34세 |
| 성별 | 남·여·무관 | 무관 |
| 소득 | 기준 중위소득 % 상한 | 150% 이하 |
| 가구 유형 | 해당 유형 목록 | 1인 가구, 신혼부부, 다자녀 |
| 취업·학업 상태 | 해당 상태 목록 | 미취업, 대학생 |
| 거주지 | 시·자치구 | 서울시, 마포구 |
| 특수 조건 | 해당 조건 목록 | 장애인, 한부모 |

  - 구조화 조건 필드가 없는 혜택은 지원 대상 텍스트에서 정규식으로 추출 (예: "만 19세 이상 34세 이하", "중위소득 150% 이하")
  - 추출에 실패한 조건은 "미상"으로 저장하고 원문을 함께 보관
- **소득 구간 변환 (브라우저)**
  - 사용자는 가구원 수와 월 소득 구간만 입력
  - 해당 연도 기준 중위소득 표로 "중위소득 몇 % 구간"을 계산하여 조건 비교에 사용
- **매칭 (브라우저)**
  - 조건마다 충족·불충족·미상 3가지로 판정 (사용자 미입력 또는 혜택 조건 미상 → 미상)
  - 혜택 판정: 불충족 조건이 하나라도 있으면 "해당 없음", 모든 조건 충족이면 "받을 수 있음", 나머지는 "확인 필요"
- **정렬 점수**
  - 1순위: 판정 그룹 (받을 수 있음 → 확인 필요)
  - 2순위: 관심 분야 일치 + 마감 임박 가중치 (마감 14일 이내 가산)
  - 미상 조건 수가 적을수록 상위
- **생활 변화 시뮬레이션**: 현재 프로필 사본에 변화를 적용하여 다시 매칭하고 두 결과를 비교

## 5. 개인정보 보호 설계
- **서버 미전송 원칙**: 혜택·조건 데이터는 서버가 정규화하여 JSON으로 제공하고, 사용자 조건 매칭은 브라우저에서만 수행
- **저장 위치**: 입력 조건, 관심 혜택, 체크리스트 상태는 브라우저(localStorage)에만 저장. "내 정보 모두 지우기" 버튼 제공
- **최소 입력**: 소득은 금액 대신 구간, 거주지는 자치구 단위, 특수 조건은 기본 미입력
- **로그 정책**: 서버 접근 로그에 조건 값이 남지 않도록 조건을 URL 쿼리에 넣지 않음
- **고지**: "참고용 판정이며 최종 자격은 신청 기관 심사로 결정" 문구를 결과 화면에 표시

## 6. 시스템 아키텍처 및 기술 스택
- **Frontend**
  - HTML5, CSS3, JavaScript (ES6+)
  - 매칭 엔진 (JavaScript 모듈), localStorage
  - Kakao Maps JavaScript SDK (Marker, services 라이브러리)
  - 캘린더 표시 및 .ics 생성
- **Backend**
  - Python FastAPI (정규화된 혜택·조건 JSON 제공, 혜택 상세 조회)
  - SQLite (혜택 원본, 정규화 조건, 갱신 이력)
  - APScheduler (혜택 데이터 일 1회 동기화)
- **Data Processing**
  - Pandas (혜택 데이터 정제)
  - 정규식 기반 조건 추출기 (Python `re`)
- **데이터 흐름**
  - 수집: 공공서비스 API → 원본 저장 → 조건 정규화 → 혜택·조건 JSON 생성
  - 조회: 브라우저가 혜택·조건 JSON 다운로드 → 브라우저에서 매칭 → 상세는 서비스 ID로 조회

## 7. 개발 단계별 워크플로우

```
[1단계: 요구사항 정의 및 데이터 소스 식별]
  └─ 공공데이터포털 공공서비스(혜택) 정보 API 활용 신청, 카카오 도메인 등록
  └─ FastAPI 기초 실습
  └─ API 응답 필드 확인, 서울시·자치구 소관 서비스 구분 방법 확정

[2단계: 데이터 수집 및 조건 정규화]  ※ 핵심 단계
  └─ 서비스 목록·상세·지원 조건 전체 수집, SQLite 저장
  └─ 구조화 조건 → 내부 스키마 변환
  └─ 지원 대상 텍스트 정규식 추출기 구현
  └─ 표본 50건 수기 라벨링으로 추출 정확도 측정 후 규칙 보정

[3단계: 매칭 엔진 구현]
  └─ 기준 중위소득 표, 소득 구간 변환 함수
  └─ 조건별 3값 판정, 혜택 판정, 정렬 점수 (JavaScript)
  └─ 가상 프로필 10종 단위 테스트

[4단계: 백엔드 API 구축]
  └─ 혜택·조건 JSON 엔드포인트 (버전·갱신 시각 포함), 혜택 상세 엔드포인트
  └─ 일 1회 동기화 작업, 변경분 반영

[5단계: 프론트엔드 및 지도 연동]
  └─ 조건 입력 마법사, 결과 목록(3그룹), 혜택 상세·체크리스트
  └─ 생활 변화 시뮬레이션 비교 화면, 마감 캘린더·.ics 내보내기
  └─ 신청 기관·주민센터 카카오맵 표시

[6단계: 통합 테스트 및 검증]
  └─ 가상 프로필 10종 결과를 정부24 혜택 상세 조건과 수기 대조
  └─ 개인 조건이 네트워크 요청에 포함되지 않는지 브라우저 개발자 도구로 확인
  └─ 모바일 화면 입력 흐름 확인
```

## 8. 기대 효과 및 한계
- **기대 효과**
  - 로그인 없이 받을 수 있는 혜택을 빠르게 확인하고 신청 준비까지 연결
  - 생활 변화에 따른 혜택 변화를 미리 확인
  - 개인 조건을 서버로 보내지 않는 구조로 개인정보 부담 최소화
- **한계**
  - 텍스트로만 제공되는 조건은 추출 오류 가능 → "확인 필요"로 안내
  - 재산, 건강보험료 등 정밀 심사 기준은 반영하지 않음
  - 판정은 참고용이며 실제 자격은 기관 심사로 결정
