# [기획안 07] 개인 경로 학습형 서울 출퇴근 이동 수단 추천 알리미

> 개발 조건: 수업 실습 프로젝트, 무료 공개 데이터만 사용, 서울 한정, 카카오맵 API 확보, 백엔드 Python FastAPI

## 1. 개요
- **프로젝트명**: 개인 경로 학습형 서울 출퇴근 이동 수단 추천 알리미
- **추진 배경**
  - 출퇴근 시간에는 버스 배차, 지하철 도착, 따릉이 재고, 날씨에 따라 그날 가장 나은 수단이 달라짐
  - 일반 길찾기 서비스는 매번 출발지·목적지를 입력해야 하고, 개인의 실제 이동 속도나 습관(걷는 속도, 환승 선호)을 반영하지 않음
- **목적**: 사용자가 등록한 출퇴근 경로 후보들에 실시간 대기 시간·재고·날씨를 결합하여 오늘 가장 적합한 수단과 출발 시각을 추천하고, 실제 이동 기록으로 개인별 소요 시간을 학습
- **타겟 사용자**: 서울에서 대중교통·따릉이로 출퇴근·통학하는 시민
- **범위**
  - 대상 수단: 서울 시내버스, 서울 지하철, 따릉이, 도보
  - 경로 탐색 API를 사용하지 않고, 사용자가 등록한 "개인 경로 템플릿"을 기준으로 계산
- **기존 서비스와의 차별점**
  - 매일 같은 경로를 반복하는 출퇴근에 특화: 앱을 열면 바로 오늘의 추천
  - 개인 실측 이동 기록으로 구간 소요 시간을 보정하여 예측이 점점 정확해짐
  - "목표 도착 시각" 기준 출발 시각 역산과 수단별 추천 이유 제시

## 2. 주요 기능
1. **개인 경로 템플릿 등록**
   - 출근·퇴근 각각 경로 후보를 2~4개 등록 (예: "버스 272 → 도보", "따릉이 직행", "지하철 2호선 → 6호선 환승")
   - 경로는 구간 목록으로 구성: 도보, 버스(노선·승차 정류소·하차 정류소), 지하철(승차역·방면·하차역), 따릉이(대여소·반납 대여소)
   - 정류소·역·대여소는 카카오맵에서 선택, 구간별 평소 소요 시간 입력
2. **오늘의 추천 카드**
   - 경로 후보별 예상 도착 시각, 대기 시간, 추천 순위
   - 추천 이유 표시 (예: "272번 2분 후 도착, 비 예보로 따릉이 제외")
3. **출발 시각 역산 및 알림**
   - 목표 도착 시각을 입력하면 경로별 늦어도 출발해야 할 시각 계산
   - 페이지가 열려 있는 동안 출발 10분 전·5분 전 브라우저 알림
4. **실시간 상태 지도**
   - 등록한 정류소·역·대여소의 실시간 도착 정보와 따릉이 대여 가능 대수·반납 가능 거치대 수 표시
   - 시작 대여소 재고가 없으면 반경 300m 내 다른 대여소 자동 제안
5. **이동 기록 및 개인 보정**
   - 출발·도착 버튼으로 실제 소요 시간 기록 (위치 추적 없음)
   - 구간별 개인 소요 시간을 기록 기반으로 보정
6. **주간 리포트**
   - 경로별 평균 소요 시간, 예측 오차, 지연 빈도 (Chart.js)

## 4. 추천 로직 설계
- **경로별 예상 소요 시간 (ETA)**: 구간별 시간의 합

| 구간 | 계산 방법 |
| :--- | :--- |
| 도보 | 구간 거리 ÷ 개인 보행 속도 (기본 1.2m/s, 기록으로 보정) |
| 버스 대기 | 정류소 도착 시각 기준 첫 번째 도착 예정 시간 (도착 전이면 두 번째 차량) |
| 버스 탑승 | 개인 구간 소요 시간 (기록으로 보정) |
| 지하철 대기 | 해당 방면 첫 번째 도착 예정 시간 |
| 지하철 탑승·환승 | 개인 구간 소요 시간 (기록으로 보정) |
| 따릉이 | 대여·반납 1분씩 + 구간 거리 ÷ 개인 자전거 속도 (기본 12km/h) |

  - 앞 구간 도착 시각을 기준으로 다음 구간의 대기 시간을 계산 (예: 정류소 도착 예정 시각에 맞는 버스 선택)
  - 실시간 정보가 없는 뒤쪽 환승 구간은 평균 대기 시간(평소 배차 간격의 절반, 사용자 입력)으로 대체
- **제외 조건**
  - 따릉이: 시작 대여소 대여 가능 0대 (대체 대여소도 없을 때), 반납 대여소 반납 가능 거치대 0개, 강수 예보
  - 실시간 도착 정보 없음: 해당 경로를 "정보 없음"으로 표시하고 평소 소요 시간으로 계산
- **추천 점수** (낮을수록 우선)
  - 점수 = ETA + 날씨 감점 + 선호 감점 + 불확실성 감점
  - 날씨 감점: 기온 33℃ 이상 또는 −10℃ 이하일 때 도보·따릉이 구간 시간 × 0.3
  - 선호 감점: 사용자가 설정한 "환승 1회당 감점(분)", "도보 싫음" 등
  - 불확실성 감점: 해당 경로 과거 예측 오차 표준편차 × 0.5
- **개인 보정 (학습)**
  - 경로 단위 실측 시간과 예측 시간 차이를 구간 비율대로 나누어 반영
  - 구간 시간 갱신: 새 값 = 0.7 × 기존 값 + 0.3 × 실측 값 (지수이동평균)
  - 비정상 기록(예측의 2배 초과) 제외
- **출발 시각 역산**: 목표 도착 시각 − 경로 ETA − 여유 시간(사용자 설정, 기본 3분)

## 5. 개인정보 보호 설계
- **위치 최소화**: 집·직장 주소를 받지 않고 정류소·역·대여소 단위로만 등록. GPS 위치 추적 없음
- **저장 위치**: 경로 템플릿, 이동 기록, 개인 보정값은 브라우저(localStorage)에만 저장. 기록 내보내기·가져오기(JSON)로 기기 이동 지원
- **서버 역할**: 실시간 API 중계와 30초 캐시만 수행하며 사용자 식별 정보 미보관. 요청에는 정류소·역·대여소 ID만 포함
- **삭제**: "기록 모두 지우기" 버튼 제공

## 6. 시스템 아키텍처 및 기술 스택
- **Frontend**
  - HTML5, CSS3, JavaScript (ES6+), PWA 구성 (홈 화면 추가)
  - Kakao Maps JavaScript SDK (Marker, CustomOverlay, services 라이브러리)
  - Chart.js (주간 리포트), localStorage, Notification API
  - ETA 계산·보정 로직 (JavaScript 모듈)
- **Backend**
  - Python FastAPI (버스·지하철·따릉이·날씨 실시간 중계)
  - 메모리 캐시 (요청 대상별 30초, 날씨 10분)
  - SQLite (정류소·역·대여소 기준 정보)
- **Data Processing**
  - Pandas (정류소·역·대여소 기준 정보 정제)
  - httpx (외부 API 비동기 호출)
  - 위경도 → 기상청 격자 좌표 변환 함수
- **데이터 흐름**
  - 앱 실행 → 등록 경로의 정류소·역·대여소 ID 목록 전송 → FastAPI가 실시간 정보 일괄 조회·캐시 → 브라우저에서 ETA·점수 계산 → 추천 카드 표시

## 7. 개발 단계별 워크플로우

```
[1단계: 요구사항 정의 및 데이터 소스 식별]
  └─ 공공데이터포털(버스·정류소·기상청), 서울 열린데이터광장(따릉이·지하철) 인증키 발급
  └─ 카카오 도메인 등록, FastAPI 기초 실습 (비동기 요청 포함)

[2단계: 기준 정보 구축]
  └─ 정류소·지하철역·따릉이 대여소 목록 수집, 좌표 정리, SQLite 저장
  └─ 카카오맵에서 선택할 수 있도록 지도 영역 조회 API 구현

[3단계: 실시간 중계 API]
  └─ 버스 도착, 지하철 도착, 따릉이 재고, 초단기예보 통합 조회 엔드포인트
  └─ 캐시, 외부 API 장애 시 "정보 없음" 응답 처리

[4단계: ETA·추천·보정 로직]  ※ 핵심 단계
  └─ 구간별 ETA 계산, 앞 구간 도착 시각 기준 대기 시간 계산
  └─ 제외 조건, 추천 점수, 출발 시각 역산
  └─ 지수이동평균 보정, 비정상 기록 제외
  └─ 가상 시나리오(비, 재고 0, 도착 정보 없음) 단위 테스트

[5단계: 프론트엔드 및 지도 연동]
  └─ 경로 템플릿 등록 화면 (지도에서 정류소·역·대여소 선택)
  └─ 오늘의 추천 카드, 실시간 상태 지도, 출발·도착 기록 버튼
  └─ 브라우저 알림, 주간 리포트 차트, PWA 설정

[6단계: 통합 테스트 및 검증]
  └─ 팀원 실제 출퇴근 2주 기록으로 예측 소요 시간 오차(MAE) 측정, 보정 전후 비교
  └─ 출퇴근 시간대 응답 속도와 외부 API 호출량 확인
  └─ 네트워크 요청에 정류소 ID 외 개인 정보가 없는지 확인
```

## 8. 기대 효과 및 한계
- **기대 효과**
  - 매일 반복되는 출퇴근 수단 선택을 실시간 근거로 빠르게 결정
  - 개인 기록으로 점점 정확해지는 예상 도착 시각
  - 위치 추적 없이 동작하는 개인 맞춤 구조
- **한계**
  - 사용자가 경로 템플릿을 직접 등록해야 하는 초기 설정 부담
  - 도로 정체 등으로 인한 버스 탑승 시간 변동은 실시간으로 반영하지 못함
  - 뒤쪽 환승 구간은 평균 대기 시간 근사
