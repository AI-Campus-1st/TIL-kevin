# [기획안 08] 한국인 영양소 섭취기준 기반 개인 맞춤 식품·식단 추천 서비스

> 개발 조건: 수업 실습 프로젝트, 무료 공개 데이터만 사용, 서울 한정, 카카오맵 API 확보, 백엔드 Python FastAPI

## 1. 개요
- **프로젝트명**: 한국인 영양소 섭취기준 기반 개인 맞춤 식품·식단 추천 서비스
- **추진 배경**
  - 보건복지부가 2025년 말 「2025 한국인 영양소 섭취기준」을 개정하여 탄수화물 비율 하향, 단백질 하한 상향, 첨가당 제한 강화 등 기준이 바뀜
  - 일반 칼로리 앱은 열량 위주이며, 하루 중 부족한 영양소를 "다음 끼니에 무엇으로 채울지"까지 안내하는 경우가 적음
- **목적**: 사용자의 신체 정보와 활동량으로 개인 권장 섭취량을 계산하고, 식사 기록과 비교하여 부족 영양소를 채우는 식품과 과다 섭취 식품의 대체 식품을 추천
- **타겟 사용자**: 식습관을 관리하려는 만 19세 이상 성인 (자취생, 직장인 등)
- **범위**
  - 대상: 만 19세 이상 성인. 임신·수유부, 질환자 맞춤 기준은 범위 밖
  - 관리 영양소: 에너지, 탄수화물, 단백질, 지방, 당류, 나트륨, 식이섬유, 칼슘 (8종)
- **기존 서비스와의 차별점**
  - 2025 개정 섭취기준을 그대로 적용하고 기준 출처를 화면에 표시
  - "남은 열량 안에서 부족 영양소를 가장 잘 채우는 식품" 추천
  - 기록한 식품 중 당류·나트륨 과다 식품의 같은 분류 대체 식품 제안

## 2. 주요 기능
1. **프로필 및 목표 설정**
   - 성별, 나이, 키, 몸무게, 신체활동 수준(4단계), 목표(유지·감량·증량)
   - 하루 권장 섭취량 계산 결과와 계산 근거 표시
2. **식사 기록**
   - 음식·가공식품 이름 검색, 1회 제공량 단위 선택(그릇, 개, g)
   - 자주 먹는 식품 즐겨찾기, 어제 식사 복사
3. **오늘의 영양 대시보드**
   - 8종 영양소의 권장량 대비 섭취 비율 막대 차트
   - 탄수화물·단백질·지방 에너지 비율과 권장 범위 비교
4. **다음 끼니 추천**
   - 남은 열량과 부족 영양소를 기준으로 음식 3~5개 추천
   - 추천 이유 표시 (예: "단백질 부족분 60% 보충, 나트륨 남은 한도 이내")
   - 제외할 재료·음식 설정 반영
5. **대체 식품 추천**
   - 기록한 식품 중 당류·나트륨이 높은 식품은 같은 식품 분류 안에서 함량이 낮은 식품 제안 (예: 가당 음료 → 무가당 음료)
6. **주간 영양 리포트**
   - 7일 평균 섭취 비율, 기준 초과·미달이 잦은 영양소 표시
7. **근처 구매처 찾기 (보조)**
   - 추천 가공식품 구매를 위한 근처 편의점·대형마트를 카카오 Places로 표시

- **2025 섭취기준 주요 반영 값**
  - 에너지 적정 비율: 탄수화물 50~65%, 단백질 10~20%, 지방 15~30%
  - 당류: 총 당류 에너지의 20% 이내, 첨가당 10% 이내로 제한
  - 나트륨·칼슘·식이섬유 등 나머지 영양소는 원문의 성별·연령별 값을 표로 입력
- **확인 필요 사항**
  - 2025 섭취기준 원문의 성인 에너지필요추정량 산식과 신체활동 계수
  - 식품영양성분 DB 음식 파일의 1회 제공량 정보 유무 (없으면 기준량 100g 기준 + 사용자 g 입력)
  - 식품안전나라 Open API의 바코드 조회 제공 여부와 식품영양성분 DB 식품코드 연계 방법

## 4. 추천 로직 설계
- **개인 권장 섭취량**
  - 에너지: 2025 섭취기준의 성별 에너지필요추정량 산식에 나이·키·몸무게·신체활동 계수 대입
  - 목표 보정: 감량 −300~−500kcal, 증량 +300kcal 범위에서 사용자 선택. 보정 후 값이 기초 수준 이하로 내려가지 않도록 하한 적용
  - 탄수화물·단백질·지방: 에너지 × 적정 비율 범위의 중앙값을 목표, 범위 전체를 허용 구간으로 표시
  - 당류: 에너지의 20%를 상한으로 환산(g), 나트륨·칼슘·식이섬유는 성별·연령별 기준값 사용
- **부족·잔여 계산**
  - 부족량 = max(0, 목표 − 현재 섭취) (단백질, 식이섬유, 칼슘)
  - 잔여 한도 = max(0, 상한 − 현재 섭취) (에너지, 당류, 나트륨)
- **다음 끼니 후보 점수**
  - 보충 점수 = Σ 가중치 × min(식품 함량, 부족량) ÷ 목표량 (부족 영양소별)
  - 초과 감점 = 에너지·당류·나트륨이 잔여 한도를 넘는 비율
  - 최종 점수 = 보충 점수 − λ × 초과 감점 (λ 기본 1.0)
  - 후보 필터: 음식 데이터 중심, 제외 재료·음식 제외, 결측 영양소가 많은 식품 제외
  - 다양성: 같은 식품 분류에서 최대 2개만 추천
- **대체 식품**
  - 대상: 1회 섭취량 기준 당류 또는 나트륨이 같은 분류 상위 25%인 기록 식품
  - 후보: 같은 식품 분류에서 해당 영양소가 30% 이상 낮고 에너지 차이가 ±30% 이내인 식품
- **데이터 품질 처리**
  - 영양성분 결측은 0이 아닌 "정보 없음"으로 처리하고 화면에 표시
  - 기준량(100g 등)과 1회 섭취 참고량을 구분하여 환산

## 5. 개인정보 보호 설계
- **민감정보 제외**: 질병, 복용 약, 임신 여부 등 건강 관련 민감정보를 받지 않음
- **저장 위치**: 프로필, 식사 기록, 제외 재료는 브라우저(localStorage)에만 저장
- **서버 전송 최소화**: 권장 섭취량 계산은 브라우저에서 수행. 추천 요청 시 신체 정보 대신 "부족량·잔여 한도 벡터와 제외 목록"만 서버로 전송
- **삭제와 이동**: "기록 모두 지우기", 기록 내보내기·가져오기(JSON)
- **고지**: "일반 성인 기준의 영양 정보이며 의료·영양 상담을 대신하지 않음" 문구 상시 표시

## 6. 시스템 아키텍처 및 기술 스택
- **Frontend**
  - HTML5, CSS3, JavaScript (ES6+)
  - 권장 섭취량·부족량 계산 모듈 (JavaScript), localStorage
  - Chart.js (영양 대시보드, 주간 리포트)
  - Kakao Maps JavaScript SDK (구매처 지도, 보조 기능)
- **Backend**
  - Python FastAPI (식품 검색, 다음 끼니 추천, 대체 식품 추천 API)
  - SQLite (식품영양성분 데이터, 식품 분류 색인, 섭취기준 표)
- **Data Processing**
  - Pandas, NumPy (영양성분 데이터 정제, 단위 환산, 후보 점수 계산)
  - 식품명 검색 색인 (SQLite FTS5 전문 검색)
- **데이터 흐름**
  - 기록: 브라우저 식품 검색 → 서버 검색 결과 → 브라우저에 기록 저장 → 브라우저에서 섭취량·부족량 계산
  - 추천: 부족량·잔여 한도 벡터 전송 → 서버 후보 점수 계산 → 상위 식품과 추천 이유 반환

## 7. 개발 단계별 워크플로우

```
[1단계: 요구사항 정의 및 데이터 소스 식별]
  └─ 식품영양성분 DB 파일·API 확보, 2025 섭취기준 원문 확보
  └─ 카카오 도메인 등록, FastAPI 기초 실습

[2단계: 영양 데이터 정제 및 기준표 구축]
  └─ 4종 영양성분 파일 통합, 단위 통일(기준량 100g·1회 섭취 참고량), 결측 표시
  └─ 식품 분류 정리, FTS5 검색 색인 생성
  └─ 2025 섭취기준 성별·연령별 값과 에너지 산식을 표로 입력

[3단계: 계산·추천 로직 구현]  ※ 핵심 단계
  └─ 권장 섭취량 계산 (브라우저 모듈), 부족량·잔여 한도 계산
  └─ 다음 끼니 후보 점수, 다양성 제한, 대체 식품 규칙 (서버)
  └─ 가상 사용자 5명 × 하루 식단 시나리오 단위 테스트

[4단계: 백엔드 API 구축]
  └─ 식품 검색, 식품 상세, 다음 끼니 추천, 대체 식품 추천 엔드포인트
  └─ 추천 응답에 점수 근거(보충 영양소, 초과 여부) 포함

[5단계: 프론트엔드 연동]
  └─ 프로필·목표 설정, 식사 기록, 영양 대시보드, 추천 카드, 주간 리포트
  └─ 구매처 지도 (보조 기능)

[6단계: 통합 테스트 및 검증]
  └─ 권장 섭취량 계산값을 섭취기준 원문 예시와 대조
  └─ 추천 결과가 남은 열량·나트륨 한도를 넘지 않는지 자동 검사
  └─ 신체 정보가 네트워크 요청에 포함되지 않는지 확인
```

## 8. 기대 효과 및 한계
- **기대 효과**
  - 최신 공식 섭취기준에 근거한 개인 권장량과 식단 피드백
  - 부족 영양소를 채우는 구체적인 다음 끼니 선택 지원
  - 신체 정보를 서버에 보내지 않는 구조
- **한계**
  - 음식 영양성분은 대표값이라 실제 조리법·분량에 따라 차이 발생
  - 사용자가 직접 기록해야 하므로 기록 누락 시 계산 정확도 저하
  - 질환·임신 등 특수 상황 기준은 제공하지 않음
