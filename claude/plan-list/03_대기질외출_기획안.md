# [기획안 03] 서울 대기질·기상 기반 건강 취약계층 외출 가이드 웹 앱

> 개발 조건: 수업 실습 프로젝트, 무료 공개 데이터만 사용, 서울 한정, 카카오맵 API 확보, 백엔드 Python FastAPI

## 1. 개요
- **프로젝트명**: 서울 대기질·기상 기반 건강 취약계층 외출 가이드 웹 앱
- **추진 배경**: 미세먼지·오존, 폭염·한파에 민감한 노인·어린이·호흡기 질환자에게 공식 기준에 근거한 외출 판단 정보와 실내 대체 장소 안내 필요
- **목적**: 에어코리아·기상청 공공 API와 공식 판정 기준을 이용하여 거점별 외출 단계(안심-주의-위험)를 판정하고, 단계가 나쁠 때 가까운 실내 시설과 쉼터를 안내
- **타겟 사용자**
  - 1차: 노인·어린이를 돌보는 보호자, 돌봄 종사자
  - 2차: 건강 취약계층 본인
  - 보호자를 주 사용자로 두어 고령자의 웹 이용 어려움 완화

## 2. 주요 기능
1. **현재 외출 단계 카드**
   - 사용자 현재 위치 기준 가장 가까운 측정소의 PM10·PM2.5·오존과 현재 기온·습도 표시
   - 판정 결과를 색상, 텍스트, 아이콘으로 함께 표시 (색각 이상 사용자 고려)
2. **거점 등록 및 거점별 단계**
   - 집, 경로당, 어린이집 등 거점 여러 곳 등록 (브라우저 저장, 로그인 없음)
   - 거점별 현재 단계를 목록으로 비교
3. **오늘 시간대별 외출 타임라인**
   - 기상 요소: 단기예보 시간별 값으로 시간대별 판정
   - 대기 요소: 대기질 예보는 하루 단위 등급만 제공되므로 "오늘·내일 예보 등급"과 "최근 6시간 실측 추이"로 표시
   - 대기질의 시간대별 예측은 근거 데이터가 없어 제공하지 않음
4. **실내 대체 시설 지도**
   - 주의·위험 단계일 때 반경 1km 내 도서관, 공공 실내체육시설, 무더위쉼터(여름)·한파쉼터(겨울) 마커 표시
   - 운영시간 정보가 있으면 현재 운영 여부 표시
5. **행동 요령 안내**: 환경부 민감군 행동요령, 기상청 폭염·한파 대비 요령 요약 (출처 명시)
6. **단계 악화 알림**
   - 1차: 페이지 접속 중 단계가 바뀌면 화면 배너와 브라우저 알림 (Notification API)
   - 2차(선택): Web Push (Service Worker 필요, iOS는 홈 화면에 추가한 PWA에서만 수신 가능)

## 3. 활용 데이터 및 API
| 데이터 | 제공처 | 주요 정보 | 갱신 | 활용 목적 |
| :--- | :--- | :--- | :--- | :--- |
| 에어코리아 측정소별 실시간 측정정보 | 공공데이터포털 (한국환경공단) | PM10, PM2.5, O3, NO2, 통합대기환경지수 | 1시간 | 현재 대기 판정 |
| 에어코리아 측정소정보 | 공공데이터포털 (한국환경공단) | 측정소명, 위경도, 주소 | 비정기 | 가까운 측정소 계산 |
| 에어코리아 대기질 예보통보 | 공공데이터포털 (한국환경공단) | 권역별 오늘·내일·모레 예보 등급 | 1일 수회 | 일 단위 예보 표시 |
| 기상청 단기예보 | 공공데이터포털 (기상청) | 시간별 기온, 습도, 강수확률, 풍속 | 1일 8회 발표 | 시간대별 타임라인 |
| 기상청 초단기실황 | 공공데이터포털 (기상청) | 현재 기온, 습도, 강수 | 1시간 | 현재 기상 판정 |
| 무더위쉼터·한파쉼터 | 공공데이터포털 (행정안전부) | 위치, 운영시간, 수용 인원 | 연 단위 | 계절별 대체 장소 |
| 서울시 공공도서관 현황 | 서울 열린데이터광장 | 위치, 운영시간, 휴관일 | 비정기 | 실내 대체 시설 |
| 서울시 공공체육시설 | 서울 열린데이터광장 | 위치, 실내·실외 구분 | 비정기 | 실내 대체 시설 |
| 카카오맵 API | Kakao Maps JavaScript SDK | 지도, Marker, CustomOverlay | | 시설 지도 |

- **사용하지 않는 데이터**
  - 노인복지시설 표준데이터: 경로당 등은 회원 이용 위주로 일반 대체 장소 안내에 부적합 → 쉼터 데이터로 대체 (쉼터에 경로당·주민센터 다수 포함)
  - S-DoT: 미세먼지 데이터 비공개로 미사용
- **확인 필요 사항**
  - 무더위쉼터·한파쉼터 데이터의 서울분 제공 형식과 갱신 시점
  - 서울시 공공도서관·체육시설 데이터셋의 정확한 명칭과 운영시간 필드 유무
  - 공공데이터포털 개발계정 일일 호출 한도

## 4. 판정 규칙 (Rule-based)
- **대기 등급 기준**: 환경부 대기질 예보 등급 구간 사용 (자체 정규화 없음)

| 항목 | 좋음 | 보통 | 나쁨 | 매우나쁨 |
| :--- | :--- | :--- | :--- | :--- |
| PM10 (㎍/㎥) | 0~30 | 31~80 | 81~150 | 151 이상 |
| PM2.5 (㎍/㎥) | 0~15 | 16~35 | 36~75 | 76 이상 |
| O3 (ppm) | 0~0.030 | 0.031~0.090 | 0.091~0.150 | 0.151 이상 |

- **기상 기준**: 기상청 폭염·한파 특보 기준 차용
  - 폭염: 체감온도 33℃ 이상 → 주의, 35℃ 이상 → 위험
  - 한파: 최저기온 −12℃ 이하 → 주의, −15℃ 이하 → 위험
- **외출 단계 판정**: 항목별 단계 중 가장 나쁜 단계를 최종 단계로 채택

| 외출 단계 | 일반 모드 | 민감군 모드 (기본값) |
| :--- | :--- | :--- |
| 안심 | 모든 대기 항목 좋음·보통, 기상 특보 기준 미만 | 모든 대기 항목 좋음·보통, 기상 특보 기준 미만 |
| 주의 | 대기 항목 중 나쁨 존재, 또는 기상 주의 기준 | 해당 없음 (한 단계 상향) |
| 위험 | 대기 항목 중 매우나쁨 존재, 또는 기상 위험 기준 | 대기 항목 중 나쁨 이상 존재, 또는 기상 주의 기준 이상 |

- 민감군 모드는 환경부 민감군 행동요령("나쁨" 단계부터 민감군 실외활동 자제)을 반영하여 한 단계 엄격하게 판정
- 판정 기준표 출처를 화면에 명시하고, "의료적 판단을 대신하지 않음" 고지

## 5. 시스템 아키텍처 및 기술 스택
- **Frontend**
  - HTML5, CSS3, JavaScript (ES6+)
  - Kakao Maps JavaScript SDK (Marker, CustomOverlay)
  - Chart.js (최근 6시간 실측 추이, 시간대별 타임라인)
  - 브라우저 Geolocation API (현재 위치), localStorage (거점 목록)
  - 접근성: 큰 글씨 기본, 고대비, 단계 표시에 색상·텍스트·아이콘 병기
- **Backend**
  - Python FastAPI (외부 API 중계, 판정 로직, 시설 조회)
  - SQLite (측정값·예보 캐시, 시설 데이터)
  - APScheduler (측정값 1시간, 예보 발표 시각 기준 주기 수집)
- **Data Processing**
  - Pandas, Requests (측정값 정제, 결측 처리)
  - 위경도 → 기상청 격자 좌표(nx, ny) 변환 함수
  - 가까운 측정소: 서울 측정소 목록(위경도)을 캐시해 두고 거리 계산으로 선택

## 6. 개발 단계별 워크플로우

```
[1단계: 요구사항 정의 및 데이터 소스 식별]
  └─ 에어코리아·기상청·행정안전부 API 활용 신청, 서울 열린데이터광장 키 발급
  └─ 카카오 도메인 등록, FastAPI 기초 실습

[2단계: 판정 규칙 정의]
  └─ 환경부 등급표, 기상청 특보 기준으로 항목별 단계 함수 작성
  └─ 일반·민감군 모드 판정 규칙 확정, 경계값 단위 테스트 작성

[3단계: 데이터 수집 및 정제]
  └─ 서울 측정소 목록 캐시, 위경도-격자 변환 함수 구현
  └─ 측정값·예보 주기 수집기 구현, SQLite 캐시
  └─ 결측값('-', 점검 중) 처리: 두 번째로 가까운 측정소 값으로 대체하고 화면에 표기
  └─ 도서관·체육시설·쉼터 데이터 정제, 실내 시설만 필터

[4단계: 백엔드 API 구축]
  └─ 위치별 현재 단계, 거점 목록 일괄 판정, 시간대 타임라인, 주변 시설 엔드포인트
  └─ 외부 API 장애 시 마지막 캐시값과 기준 시각 반환

[5단계: 프론트엔드 및 지도 연동]
  └─ 외출 단계 카드, 거점 목록, 타임라인 차트, 시설 지도
  └─ 화면 배너·브라우저 알림 구현, 여유가 있으면 Web Push 추가

[6단계: 통합 테스트 및 검증]
  └─ 판정 경계값 테스트 (예: PM2.5 35/36, 체감온도 32.9/33.0)
  └─ 결측·API 장애 시 화면 동작 확인
  └─ 큰 글씨·고대비 모드에서 모바일 화면 확인
```

## 7. 기대 효과 및 한계
- **기대 효과**
  - 공식 기준에 근거한 외출 판단 정보와 실내 대체 장소를 한 화면에서 제공
  - 보호자가 여러 거점의 상태를 한 번에 확인
- **한계**
  - 측정소 간격이 수 km 단위로 거점 위치의 대기질을 정확히 대표하지 못함
  - 대기질 시간대 예측은 제공하지 않음
  - 개인 건강 상태를 반영하지 않는 일반 기준 판정
