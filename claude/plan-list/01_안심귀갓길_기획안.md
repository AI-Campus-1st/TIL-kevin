# [기획안 01] 서울 도보 네트워크 기반 방범 시설 연계 귀갓길 경로 안내 서비스

> 개발 조건: 수업 실습 프로젝트, 무료 공개 데이터만 사용, 서울 한정, 카카오맵 API 확보, 백엔드 Python FastAPI

## 1. 프로젝트 개요
- **목적**: 서울시 도보 네트워크와 방범 시설 위치 데이터를 결합하여, 최단 경로와 "방범 시설 경유 경로"를 나란히 비교 제시하는 웹 서비스
- **타겟 사용자**: 야간에 도보로 귀가하는 서울 시민 (1인 가구 포함)
- **범위**
  - 1차: 서울 1~2개 자치구 (도보 네트워크 규모와 자치구별 보안등 데이터 편차 고려)
  - 2차: 데이터가 확보된 자치구로 확장
- **표현 원칙**
  - "안전 경로", "안전 지수" 대신 "방범 시설 경유 경로", "방범 시설 점수" 사용
  - 시설 밀도는 안전을 보장하지 않으므로, 서비스 전반에 "시설 위치 기반 참고 경로" 고지

  - 통합관제센터 연계: 기관 협약 사항으로 실습 범위 밖

## 3. 데이터 접근 가능성 및 API 획득 검토
- **서울 열린데이터광장 / 공공데이터포털**
  - 도보 네트워크, 안심귀갓길, CCTV, 비상벨, 보안등은 파일(CSV, SHP) 다운로드 방식. 정적 데이터이므로 1회 전처리 후 서버에 저장
- **카카오 API**
  - JavaScript 키 확보 완료. 카카오 개발자 콘솔에 사이트 도메인(개발 시 `http://localhost` 포함) 등록 필요
  - 지구대·파출소 주소 → 좌표 변환은 카카오 로컬 REST API(같은 앱의 REST 키) 또는 JS SDK `services.Geocoder`로 1회 변환 후 저장
  - 출발지·목적지 입력은 JS SDK `services.Places` 키워드 검색 사용
- **확인 필요 사항**
  - 대상 자치구의 보안등 위치 데이터 제공 여부
  - 도보 네트워크 링크 유형 코드표의 육교·지하보도·계단 구분 여부
  - 생활안전지도 범죄주의구간 Open API의 사용 조건 (확장 검토용)

## 4. 개인정보·보안 검토
- 출발지·목적지는 거주지 노출 위험이 있으므로 서버 DB·로그에 저장하지 않음
- 경로 요청 좌표는 URL 쿼리가 아닌 POST 본문으로 전달
- 공공데이터 인증키·카카오 REST 키는 FastAPI 서버 환경변수로만 관리
- 화면 하단과 경로 결과에 "시설 위치 기반 참고 경로이며 안전을 보장하지 않음" 고지 상시 표시

## 5. 데이터 정확도 및 정제 방안
- **정확도 이슈**
  - 도보 네트워크는 2020년 기준 구축으로 이후 신설·변경 도로 미반영 가능
  - 시설 위치는 실제 감시 범위(CCTV 화각, 작동 여부)를 나타내지 않음
  - 보안등 데이터는 자치구별 편차가 커서 자치구 간 점수 비교에 부적합
- **정제 방안**
  - **좌표 검증**: 서울 경계 밖 좌표, 결측 좌표, 동일 좌표 중복 제거
  - **그래프 정합성**: 도보 네트워크를 그래프로 변환 후 가장 큰 연결 요소만 사용, 끊긴 링크 확인
  - **가중치 설계**
    - 링크별 반경 30m 버퍼 내 시설 수를 유형별 가중 합산 (CCTV, 비상벨, 보안등, 지구대)
    - 링크 비용 = 링크 길이 × (1 − α × 정규화 시설 점수), α는 0~0.5 범위에서 2~3개 값 비교
    - 지정 안심귀갓길 링크는 추가 감산
    - 최단 경로 대비 1.3배를 넘는 우회 경로는 제시하지 않음
  - **행정동 단위 지표**: 시설 수를 그대로 쓰지 않고 도로 길이 1km당 시설 수로 정규화

## 6. 주요 기능
1. **방범 시설 지도**
   - CCTV·비상벨·보안등·지구대·편의점 레이어를 켜고 끄는 방식으로 표시
   - 마커가 많은 구간은 MarkerClusterer 적용
2. **경로 비교**
   - 출발지·목적지를 장소 검색으로 입력
   - 최단 경로(회색)와 방범 시설 경유 경로(강조 색)를 Polyline 2개로 동시 표시
   - 거리, 예상 소요 시간, 경로상 시설 수를 비교 표로 제공
3. **지정 안심귀갓길 표시**: 서울시 지정 안심귀갓길 구간을 별도 레이어로 표시
4. **행정동 방범 시설 밀도 지도**
   - 도로 길이 1km당 시설 수를 행정동 Polygon 색상으로 표시 (단계구분도)
5. **비상 연락 바로가기**
   - `tel:112` 연결 버튼
   - 현재 위치 기준 가장 가까운 지구대·파출소 위치와 전화번호 표시

## 7. 시스템 아키텍처 및 기술 스택
- **Frontend**
  - HTML5, CSS3, JavaScript (ES6+)
  - Kakao Maps JavaScript SDK (Marker, MarkerClusterer, Polyline, Polygon, services 라이브러리)
- **Backend**
  - Python FastAPI (경로 탐색 API, 시설 조회 API)
  - 전처리 결과는 파일로 저장 (그래프: GraphML 또는 pickle, 시설: GeoJSON). 정적 데이터이므로 별도 DB 불필요
- **Data Processing**
  - Pandas, GeoPandas (시설 좌표 정제, 버퍼 집계)
  - NetworkX (도보 그래프 구성, 다익스트라 최단 경로)
  - Shapely (버퍼, 근접 노드 탐색)
- **데이터 흐름**
  - 전처리: 원천 파일 → 정제 → 링크별 시설 점수 계산 → 그래프 파일 저장
  - 조회: 출발·도착 좌표 → 가장 가까운 노드로 스냅 → 다익스트라 2회(거리 기준, 가중치 기준) → GeoJSON 응답 → Polyline 표시

## 8. 개발 워크플로우

```
[1단계: 환경 준비]
  └─ 공공데이터 다운로드 계정, 카카오 도메인 등록
  └─ FastAPI 기초 실습 (라우팅, POST 본문 처리, CORS 설정)

[2단계: 데이터 확보 및 대상 자치구 선정]
  └─ 자치구별 보안등 데이터 제공 여부 확인 후 대상 자치구 1~2곳 확정
  └─ 도보 네트워크, 안심귀갓길, CCTV, 비상벨, 지구대 데이터 다운로드

[3단계: 전처리]
  └─ 시설 좌표 검증, 서울 경계 필터, 중복 제거
  └─ 지구대·파출소 주소 → 좌표 변환
  └─ 도보 네트워크 → NetworkX 그래프 변환, 연결성 검사

[4단계: 가중치 설계]
  └─ 링크 버퍼 내 시설 집계, 비용 함수 정의
  └─ α 값 2~3개로 경로 결과 비교 후 기본값 결정

[5단계: 백엔드 API 구현]
  └─ 시설 조회 API (영역 범위 내 시설 GeoJSON)
  └─ 경로 탐색 API (최단·가중 경로, 거리·시간·시설 수 요약)

[6단계: 프론트엔드 및 카카오맵 연동]
  └─ 시설 레이어·클러스터, 경로 2개 Polyline, 비교 표, 행정동 단계구분도

[7단계: 테스트 및 검증]
  └─ 대상 자치구 출발·도착 쌍 30개 샘플로 우회율, 경로상 시설 수 증가율 측정
  └─ 경로 API 응답 시간 측정 (목표: 1초 이내)
  └─ 1~2개 경로 현장 확인 (선택)
```

## 9. 기대 효과 및 한계
- **기대 효과**
  - 최단 경로와 방범 시설 경유 경로를 수치로 비교하여 경로 선택 근거 제공
  - 서울시 지정 안심귀갓길 정보 접근성 향상
- **한계**
  - 범죄 발생 데이터를 사용하지 않아 실제 위험도를 반영하지 못함
  - 시설 위치 데이터로 실제 감시·조명 수준을 대신함
  - 2020년 기준 도보 네트워크로 최신 도로 변화 미반영
