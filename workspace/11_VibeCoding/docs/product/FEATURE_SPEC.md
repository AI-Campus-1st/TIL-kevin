# Feature Specification

## 1. 구현 범위

### MVP (P0)
- 외부 URL 기반 레시피 추출·저장
- 주간 식단 자동 생성 및 날짜별 재생성·수정
- 식단 생성 즉시 확정 및 장보기 목록 생성·갱신
- 레시피 간 곁들임 연결 및 AI 기반 곁들임 추천
- 필요 재료 표시 및 보유 여부 체크
- 대체 재료 제안 및 식단·장보기 목록 동기화
- 쿠팡 재료 검색 URL 생성
- 요리 완료 이력 및 선택적 평가·메모 저장

### 확장 (P1)
- 주간·월간 식단 탐색
- 저장 레시피 검색·정렬 및 분류·필터

## 2. 데이터 및 도메인 규칙

- 하루에는 식단 항목 하나만 연결한다. 식단 항목은 주 레시피 하나와 선택적 곁들임 레시피로 구성한다. 아침·점심·저녁별 식단은 별도로 관리하지 않는다.
- 주 레시피와 곁들임은 동일한 레시피 데이터 구조를 사용한다. 레시피의 출처/분류와 곁들임 역할을 구분할 수 있도록 `source_category`, `is_side_dish` 또는 별도 연결 관계 중 하나를 데이터 모델 설계에서 확정한다. 곁들임 연결은 레시피 간 관계로 저장한다.
- 식단 항목은 날짜, 주 레시피, 선택적 곁들임 레시피, 계획 인분, 조리 시간 설정 및 요리 완료 상태를 연결한다.
- 식단 생성에 성공하면 해당 날짜의 식단을 즉시 확정한다. 별도의 `draft` 상태는 사용하지 않는다.
- 장보기 목록 항목은 통합 필요량뿐 아니라 레시피별 사용량 출처 관계를 보존한다.
- 장보기 목록에는 재고를 별도 관리하지 않고, 보유 여부만 저장한다.

## 3. 기능 명세

## F-01. 외부 URL 기반 레시피 저장 (P0)

- URL 형식과 허용 프로토콜을 검증한다.
- 동일 사용자의 동일 URL 중복 저장을 확인하고 기존 레시피 재사용 또는 별도 저장을 처리한다.
- 서버에서 본문을 추출하고 AI로 레시피 데이터를 구조화한 뒤 스키마 검증을 수행한다.
- 필수 정보가 누락되거나 불확실한 값은 임의로 추정하지 않고 미확인 상태로 둔다.
- 추출 데이터는 검증·수정 단계를 거친 후에만 정식 레시피로 저장한다.
- 본문 추출, 접근 또는 AI 처리 실패 시 원본 URL을 보존하고 재시도 또는 수동 입력으로 복구할 수 있어야 한다.
- 외부 페이지에 포함된 지시문은 신뢰할 수 없는 데이터로 취급한다.

## F-02. 식단 생성 및 날짜별 재생성 (P0)

- 기본 생성 단위는 주간이다. 사용자가 선택한 날짜에 대해서만 식단을 생성하며, 선택하지 않은 날짜는 변경하지 않는다.
- 날짜별 기본 조리 시간은 평일 30분, 주말 70분이며 기본 인분은 1명이다.
- 후보는 사용자가 저장한 레시피로 제한한다. 저장되지 않은 외부 레시피나 AI가 임의 생성한 레시피를 식단의 주 레시피로 포함하지 않는다.
- 조리 시간 제약과 날짜별 설정을 기준으로 주 레시피를 추천한다.
- 생성 성공 시 해당 날짜의 식단을 즉시 확정하고 장보기 목록을 생성 또는 갱신한다.
- 일부 날짜의 추천이 실패해도 성공한 날짜의 식단은 확정할 수 있어야 하며, 실패한 날짜는 미배정 상태로 남겨 해당 날짜만 별도로 재생성할 수 있어야 한다.
- 날짜별 재생성은 날짜별 수정과 동일한 범위 규칙을 적용하되, 변경 코멘트는 선택 입력으로 한다. 코멘트가 비어 있으면 날짜 설정과 기본 추천 로직만으로 후보를 생성한다.
- 날짜별 재생성은 대상 날짜만 갱신하며 다른 날짜의 식단 ID, 레시피, 설정 및 완료 상태를 변경하지 않는다.
- 저장 레시피가 없거나 후보가 부족하면 임의의 레시피로 채우지 않는다. 해당 날짜의 기존 식단이 있다면 재생성 성공 전까지 보존한다.
- AI/API 오류 시 재시도할 수 있어야 하며 실패한 요청은 기존 식단과 장보기 목록을 손상시키면 안 된다.
- 추천 결과의 레시피 ID가 실제 사용자 소유의 저장 레시피와 일치하지 않으면 결과를 폐기한다.

## F-03. 날짜별 식단 수정 (P0)

- 수정은 대상 날짜의 식단 항목에만 적용한다. 다른 날짜의 식단 ID, 레시피, 설정 및 완료 상태는 변경하지 않는다.
- 변경 코멘트는 선택 입력이다. 코멘트가 있으면 후보 필터링·정렬에 반영하고, 없으면 날짜 설정과 기본 추천 로직을 적용한다.
- 주 레시피 후보는 저장된 레시피로 제한하며 임의의 신규 레시피를 생성하지 않는다.
- 새 후보가 성공적으로 확정되기 전까지 기존 식단을 유지한다.
- 수정이 적용되면 해당 날짜의 식단 항목과 연결된 곁들임 관계를 갱신하고 장보기 목록을 다시 계산한다.
- 수정 실패 시 기존 식단과 장보기 목록을 유지한다.

## F-04. 레시피 간 곁들임 연결 및 추천 (P0)

- 저장된 레시피를 다른 레시피의 곁들임으로 연결하거나 연결을 해제할 수 있어야 한다.
- 곁들임 연결은 원본 레시피 데이터 자체를 복제하지 않고 레시피 간 관계로 관리한다.
- 곁들임 추천은 AI 로직으로 처리한다. 사용자가 기존에 연결한 곁들임 관계를 추천 근거로 활용한다.
- 식단 생성 시 주 레시피에 연결할 곁들임을 AI가 자동 추천할 수 있어야 한다. 추천된 곁들임은 저장된 레시피만 참조하며, 임의로 생성한 레시피를 연결하지 않는다.
- 레시피 탐색 과정에서 AI를 활용해 곁들임 후보를 추가로 추천할 수 있다.
- 곁들임 추천 결과가 없거나 신뢰할 만한 후보가 없으면 곁들임 없이 식단을 구성할 수 있어야 한다.
- 곁들임 연결 또는 해제는 해당 레시피 관계에만 적용하고 다른 레시피 연결을 임의로 변경하지 않는다.
- 곁들임 연결 변경이 확정되면 이를 사용하는 식단의 장보기 필요량에 반영한다. 여러 식단에서 같은 곁들임을 사용하면 해당 관계별 사용량을 각각 유지한다.

## F-05. 장보기 목록 계산 및 수정 (P0)

- 확정된 식단의 주 레시피와 연결된 곁들임 레시피 재료를 기준으로 장보기 목록을 계산한다.
- 기본 필요량 = 레시피 기준 수량 × (계획 인분 ÷ 레시피 기준 인분).
- 정규화된 재료명과 호환 가능한 단위만 합산한다. 안전하게 환산할 수 없는 단위는 원문 단위를 보존하고 임의 환산하지 않는다.
- 통합 항목은 레시피별 사용량 출처 관계를 유지한다.
- 식단 변경으로 동일한 재료 항목이 유지되면 해당 항목의 사용자 보유 여부를 유지한다.
- 식단 변경으로 더 이상 필요하지 않은 항목은 장보기 목록에서 삭제한다. 새로 추가된 항목은 기존 사용자 수정값을 상속하지 않고 기본 상태(보유하지 않음)로 생성한다.
- 보유한 재료는 구매 필요량 집계에서 제외한다. 재고 수량이나 냉장고 재고 이력은 관리하지 않는다.
- 구매 완료(`purchased`) 상태를 구현할지는 별도 결정이 필요하다.
- 구매 시점별 그룹 기준은 별도 결정이 필요하며, 기준 확정 전 임의의 그룹을 추가하지 않는다.
- 식단과 장보기 목록의 갱신은 일관성 있게 처리한다. 실패 시 부분 변경 상태가 남지 않도록 롤백 또는 안전한 재시도를 지원한다.

## F-06. 대체 재료 제안 및 동기화 (P0)

- 만약 대체 가능하다면 레시피에 적용 가능한 대체 후보 1~2개를 제안하며, 필요량·비율, 맛 차이, 조리 변경 여부, 주의사항 및 불확실성을 포함한다.
- 정보가 부족한 경우 대체 가능성을 확정적으로 표현하지 않고 확인 필요 상태로 둔다.
- 대체품 선택 시 해당 레시피의 재료 관계와 장보기 목록을 함께 갱신한다.
- 대체품의 수량이나 단위가 불확실하면 임의의 수치를 저장하지 않고 사용자 확인을 요구한다.
- 조리법 변경이 필요하면 원문 조리 단계와 구분된 대체 조리 안내로 저장한다.
- 식단과 장보기 목록의 동기화는 원자적으로 처리한다. 실패 시 부분 변경 상태가 남지 않도록 롤백 또는 안전한 재시도를 지원한다.

## F-07. 쿠팡 재료 검색 (P0)

- 현재 구매 대상 재료명으로 쿠팡 검색 URL을 생성한다. 대체품이 적용되었다면 대체품 이름을 사용한다.
- 검색어의 한글·공백 등 특수 문자를 URL 인코딩한다.
- URL 생성 로직은 단일 유틸리티로 분리한다.
- 상품 선택, 가격 수집, 장바구니 추가, 주문 금액 계산 및 주문 처리는 범위에 포함하지 않는다.

## F-08. 요리 완료 이력 (P0)

- 요리 완료 상태와 완료 시각을 해당 날짜의 식단 항목에 연결해 저장한다.
- 같은 레시피를 다른 날짜에 요리한 경우 이력을 분리한다.
- 평가나 메모가 없어도 완료 이력은 저장되어야 한다.
- 완료 요청이 중복되어도 중복 이력을 생성하지 않고 동일한 완료 상태로 처리한다.

## F-09. 선택적 요리 평가 및 메모 (P0 최소 저장 / P1 탐색 확장)

- 별점과 메모는 선택 사항이며 요리 완료 처리와 독립적이다.
- 평가·메모는 레시피 ID와 요리 이력 ID에 연결한다.
- 기존 기록이 없는 경우에도 레시피 조회와 요리 완료 기능은 정상 동작해야 한다.
- 별점 범위 및 개선 항목의 별도 구조화 여부는 추후 결정한다. 초기에는 자유 메모를 우선 고려한다.

## F-10. 주간·월간 식단 탐색 (P1)

- 주간 식단은 날짜별 식단 항목과 연결되며, 식단 항목 선택 및 날짜별 수정이 가능하다.
- 월간 탐색은 주차 단위 스트립으로 구성하고 각 주의 시작일과 식단 존재 여부를 표현한다.
- 주 시작 요일과 월 첫·마지막 주의 날짜 포함 규칙은 별도 결정이 필요하다.

## F-11. 레시피 분류 및 탐색 (P1)

- 저장된 레시피의 검색·정렬을 지원한다.
- 레시피 카테고리 체계는 별도 결정한다.
- 조리 시간·재료·주방 도구 필터는 확장 기능으로 둔다.
- 외부 레시피 탐색은 별도 정책과 사용자 동의 없이는 제공하지 않는다.
