# SCREEN.md — 화면 명세 초안

> **목적**: 사용자 시나리오와 기능명세 F-01~F-10을 실제 화면 단위로 정리하고, 화면 구성·행동·전환·예외 상태의 구현 기준을 제안한다.
> **범위**: MVP(P0)를 중심으로 작성하고 확장 기능(P1)은 별도 표시한다.
> **화면 환경**: 웹으로 구현하되 모바일 앱처럼 사용한다. 기준 캔버스는 `390 × 844 CSS px`, 최대 너비는 `430px`이며 데스크톱에서도 중앙에 동일한 앱 프레임을 표시한다. 반응형 데스크톱 레이아웃은 만들지 않는다.
> **관련 문서**: `design.md`, `FEATURE_SPEC.md`, `SCENARIO.md`

## 1. 화면 설계 원칙

1. 화면은 사용자가 수행하려는 작업 단위로 나눈다. 모든 작업을 모달에 넣지 않고, 목록·편집·상세처럼 충분한 공간이 필요한 작업은 독립 화면으로 둔다.
2. 모달/바텀시트는 현재 화면의 맥락을 유지한 채 짧게 처리할 작업에 사용한다. 예: 중복 URL 안내, 재료 사용 출처, 대체 재료 선택.
3. 식단 생성 결과는 `초안`, 사용자 확정 후 `확정`, 요리 완료 후 `완료`로 구분한다. 확정 전에는 확정 장보기 목록을 생성하지 않는다.
4. 메뉴 변경은 선택한 날짜만 대상으로 한다. 새 후보를 적용하기 전까지 기존 메뉴를 유지한다.
5. 대체 재료는 사용자가 선택한 레시피/메뉴에만 적용한다. 다른 메뉴에서 사용하는 동일 재료의 수량은 보존한다.
6. 정보가 추출되지 않았거나 수량·단위가 불확실하면 임의의 값을 만들지 않고 `미확인` 또는 `확인 필요`로 표시한다.
7. 보유 재료는 목록에서 표시만 관리한다. 냉장고 재고 수량이나 재고 이력은 만들지 않는다.
8. 별점 범위, 구매 그룹, 단위 변환, 월간 주차 산정처럼 미확정인 정책은 화면 명세에서 확정값처럼 표현하지 않는다.
9. 홈은 오늘의 메뉴와 주간 식단을 우선 노출한다. 전체 재료 목록이나 대체 재료 안내처럼 부가적인 정보는 접은 글(Disclosure) 안에 배치해 기본 화면의 시각적 밀도를 낮춘다.

## 2. 정보 구조 및 화면 목록

### 2.1 1차 진입 구조 제안

**하단 내비게이션 제안**: `홈` / `식단` / `장보기` / `레시피`

- `홈`: 오늘의 메뉴와 주요 작업 바로가기
- `식단`: 주간 식단 조회·생성·수정
- `장보기`: 확정 식단의 통합 재료 목록
- `레시피`: 저장한 레시피 목록과 URL 저장

하단 내비게이션은 기능명세에 명시된 고정 요구사항이 아니라, 주요 기능 간 이동을 단순화하기 위한 IA 제안이다. 실제 화면에서는 현재 선택한 탭을 명확히 표시한다. 레시피 상세 및 편집 작업은 해당 탭 안에서 진입하는 하위 화면으로 둔다.

## 3. 공통 앱 프레임

### `APP-01` — 모바일 앱 프레임

- **캔버스**: 기준 `390 × 844 CSS px`, 최대 너비 `430px`; 데스크톱에서도 같은 비율의 앱 프레임으로 중앙 정렬한다.
- **스크롤**: 콘텐츠 영역만 세로 스크롤한다. 하단 내비게이션은 고정할 수 있으나, 화면 높이가 짧을 때 본문과 CTA가 겹치지 않도록 안전 여백을 둔다.
- **공통 헤더**: 화면 제목, 필요 시 뒤로가기, 날짜/주차 정보, 화면의 주요 보조 액션.
- **공통 상태 표현**: `초안`, `확정`, `완료`, `보유함`, `확인 필요`, `미확인`은 텍스트와 아이콘/형태를 함께 사용한다. 색상만으로 상태를 표현하지 않는다.
- **공통 상태 UI**: 로딩, 빈 상태, 오류, 재시도, 저장 완료 토스트를 재사용한다.
- **작업 유지**: 모달을 닫아 원 화면으로 돌아올 때 목록의 스크롤 위치와 입력 상태를 가능한 한 유지한다.

## 4. 홈

### `HOME-01` — 홈

**목적**: 앱 진입 직후 오늘 조리할 메뉴와 주간 식단 등 가장 중요한 정보를 빠르게 확인하게 한다. 재료의 세부 정보와 대체 재료 탐색은 보조 정보로 취급해 접은 글 안에 배치한다.

**구성**
1. **상단**: 서비스 로고/명칭, 오늘 날짜.
2. **오늘의 메뉴 카드 — 최우선 영역**
   - 오늘 확정 메뉴가 있으면 레시피명, 예상 조리 시간, 완료 상태, 주요 재료 미리보기를 표시한다. 주요 재료 미리보기는 핵심 재료 2~3개 또는 짧은 한 줄로 제한한다.
   - 전체 재료명과 수량은 기본 노출하지 않고 아래 `필요 재료 확인` 접은 글에서 확인한다.
   - 완료된 메뉴는 `완료` 상태를 표시한다.
   - 카드의 제목/대표 영역 선택 시 `COOK-01`로 이동한다.
   - 메뉴가 없으면 빈 상태와 `주간 식단 보기` CTA를 제공한다.
3. **접은 글 — `필요 재료 확인`**
   - 기본 상태는 **접힘**이다. 제목 옆에 펼침/접힘을 알리는 chevron 아이콘을 둔다.
   - 펼치면 오늘 메뉴의 재료명, 계획 인분 기준 수량·단위를 목록으로 표시한다. 수량이 불확실하면 `미확인`으로 표시한다.
   - `장보기에서 전체 재료 보기` 액션을 제공하고 `SHOP-01`로 이동한다. 확정 장보기 목록이 없으면 해당 액션 대신 식단 확정 후 장보기 목록을 만들 수 있다는 안내를 표시한다.
4. **접은 글 — `대체 재료 확인`**
   - 기본 상태는 **접힘**이며, 확정 식단/장보기 목록이 있을 때 보조 항목으로 표시한다. 장보기 목록이 없으면 노출하지 않는다.
   - 펼치면 대체 재료는 특정 레시피에 한해 적용되며 장보기 목록과 함께 갱신된다는 짧은 설명과 `장보기에서 대체 재료 찾기` 액션을 표시한다.
   - 홈에서는 대체 재료를 직접 선택하거나 전역 적용하지 않는다. 재료 행 및 대상 레시피를 명확히 선택할 수 있도록 `SHOP-01`에서 대체 흐름을 시작하고, 필요 시 `SHOP-03`으로 이동한다.
5. **주간 식단 요약**
   - 현재 주의 날짜별 메뉴 요약과 식단 상태를 표시한다.
   - 식단이 없으면 `이번 주 식단 만들기` CTA를 제공한다.
   - 선택 시 `PLAN-01`로 이동한다.
6. **장보기 요약**
   - 확정 식단의 장보기 목록이 있으면 구매 대상 항목 수 등 확인 가능한 요약과 `장보기 보기` CTA를 제공한다.
   - 확정된 식단이 없으면 식단 생성/확정 경로를 안내한다.
7. **레시피 바로가기**: `레시피 URL 저장` 및 `레시피 보관함` 진입을 제공한다.

**접은 글 컴포넌트 규칙 (`DISC-01`)**
- 기본 상태는 접힘이며, 사용자가 직접 눌러 펼친다. 핵심 정보나 주요 CTA를 접은 글 안에만 숨기지 않는다.
- 접힌 상태에서도 제목으로 내용과 목적을 알 수 있게 쓴다. 예: `필요 재료 확인`, `대체 재료 확인`.
- 펼침/접힘 상태를 chevron 아이콘과 접근성 상태(`aria-expanded`)로 함께 표현한다. 색상만으로 상태를 구분하지 않는다.
- 펼쳐진 내용은 인라인 영역으로 표시하며, 별도 모달을 띄우지 않는다.
- 접은 글 안에서 이동한 뒤 돌아왔을 때 가능한 한 이전 스크롤 위치와 펼침 상태를 유지한다.

**주요 동작**

| 동작 | 결과 |
|---|---|
| 오늘 메뉴 대표 영역 선택 | `COOK-01` |
| `필요 재료 확인` 펼치기 | 오늘 메뉴의 전체 재료/수량을 인라인 표시 |
| `장보기에서 전체 재료 보기` | `SHOP-01` |
| `대체 재료 확인` 펼치기 | 대체 재료 흐름 안내 및 장보기 이동 CTA 표시 |
| `장보기에서 대체 재료 찾기` | `SHOP-01`; 대상 재료 행에서 `SHOP-03` 진입 |
| 주간 식단 보기 | `PLAN-01` |
| 이번 주 식단 만들기 | `PLAN-02` |
| 장보기 보기 | 확정 목록이 있으면 `SHOP-01` |
| 레시피 URL 저장 | `RECIPE-02` |
| 레시피 보관함 | `RECIPE-01` |

**상태**
- 오늘 메뉴 없음: 조리 화면으로 이어지는 잘못된 빈 카드 대신 식단 보기 CTA를 제공한다. 오늘 메뉴 종속 접은 글도 표시하지 않는다.
- 저장 레시피 0개: 식단 생성 화면에서 레시피 등록을 안내한다.
- 확정 식단 없음: 확정 장보기 목록이나 대체 재료 선택 기능이 있는 것처럼 표시하지 않는다.
- 재료량 미확인: 값을 추측하지 않고 `미확인`을 표시한다.

## 5. 식단 화면

### `PLAN-01` — 주간 식단

**목적**: 생성된 주간 식단을 조회하고, 초안은 이어서 검토하며 확정된 식단은 날짜별 조리 화면으로 연결한다.

**구성**
- 상단: 주차 범위, 이전/다음 주 이동, 식단 상태.
- 날짜별 세로 카드/목록: 날짜·요일, 레시피명, 예상 조리 시간, 주요 재료, 곁들임 메뉴(있는 경우), 완료 여부.
- 각 날짜 메뉴 선택 시 `COOK-01`로 이동.
- 초안인 경우 `초안 검토` CTA로 `PLAN-03` 진입.
- 확정 식단이 없는 주는 `식단 생성` CTA로 `PLAN-02` 진입.
- `월간 보기` 진입을 제공할 경우 `PLAN-05` 보기 모드를 연다(P1).

**동작 규칙**
- 사용자가 선택하지 않은 날짜에는 메뉴가 배정되지 않는다.
- 메뉴 변경은 해당 날짜 카드의 `메뉴 변경`으로 시작한다.
- 다른 날짜의 메뉴/설정/완료 상태는 이 화면에서 변경되지 않아야 한다.

### `PLAN-02` — 식단 생성 설정

**목적**: 식단 생성에 필요한 최소한의 날짜·시간·인원 설정을 입력한다.

**구성**
- 이번 주 날짜 선택 UI. 사용자가 선택한 날짜에만 메뉴를 생성한다.
- 선택한 날짜별 조리 가능 시간 입력: 평일 기본 `30분`, 주말 기본 `70분`.
- 식사 인원: 기본 `1명`.
- 안내 문구: 저장된 레시피만 추천 후보로 사용한다.
- 하단 주요 CTA: `식단 생성`.
- 저장 레시피가 0개이면 `레시피 URL 저장` CTA와 빈 상태 설명을 제공한다.

**동작 및 상태**
- 기본값으로 시작할 수 있어 필수 설정 외 입력을 최소화한다.
- 생성 중 로딩 상태와 중복 제출 방지를 적용한다.
- 오류가 나도 기존 초안을 자동으로 덮어쓰지 않고 재시도를 제공한다.
- 성공하면 `PLAN-03`으로 이동하며 결과 상태는 `초안`이다.
- 시간 초과 레시피 처리 및 후보 부족 시 정책은 Q-06 확정 전까지 임의로 고정하지 않는다.

### `PLAN-03` — 식단 초안 검토

**목적**: 날짜별 추천을 비교하고 필요한 메뉴만 변경한 뒤 식단을 확정한다.

**구성**
- 상단: 대상 주차, `초안` 상태.
- 날짜별 메뉴 카드: 날짜, 레시피명, 예상 조리 시간, 주요 재료, 곁들임(있는 경우).
- 메뉴 미배정 날짜는 `메뉴 없음`과 이유를 표시한다.
- 날짜별 `메뉴 변경` 액션.
- 하단 `식단 확정` CTA.

**동작 및 규칙**
- 후보는 사용자가 저장한 레시피로 한정한다.
- 기본은 날짜당 핵심 요리 1개다. 곁들임은 있는 경우 별도로 표시한다.
- 특정 날짜의 변경은 `PLAN-04`에서만 수행하고, 적용 전까지 기존 후보를 보존한다.
- `식단 확정` 시 `DIALOG-01`을 표시하는 방식을 제안한다. 확정 후에는 식단 상태를 `확정`으로 바꾸고 인분 기준 재료량을 계산해 `SHOP-01`을 생성한다.
- 후보가 부족한 날짜는 부족 사유를 명시한다. 저장하지 않은 외부 레시피를 자동으로 섞지 않는다.

### `PLAN-04` — 날짜별 메뉴 변경

**목적**: 주간 식단 중 사용자가 선택한 한 날짜의 메뉴만 교체한다.

**구성**
- 변경 대상 날짜와 현재 메뉴.
- 필수 자연어 요청 입력란(예: `더 간단하고 설거지가 적은 메뉴`).
- 후보 재생성 CTA.
- 추천 후보 목록: 레시피명, 예상 조리 시간, 주요 재료.
- 각 후보에 `이 메뉴로 변경` 액션.

**동작 및 규칙**
- 요청사항은 후보 필터링/정렬에 반영한다. 저장되지 않은 신규 레시피를 AI가 임의 생성하지 않는다.
- 후보가 없으면 그 이유와 재입력/다른 요청 경로를 제공한다.
- 후보 선택 전에는 기존 메뉴를 유지한다.
- `이 메뉴로 변경` 선택 시 대상 날짜만 갱신하고 `PLAN-03` 또는 `PLAN-01`로 돌아온다. 불필요한 확인창은 추가하지 않는다.
- 확정 식단의 변경은 관련 장보기 목록 재계산과 연결된다. 사용자 구매 수량 보존 정책은 Q-10 확정 전까지 명시적으로 미정 처리한다.

### `PLAN-05` — 월간 주차 스트립 (P1)

**형태**: 별도 달력 화면이 아닌 `PLAN-01`의 월간 보기 모드.

**구성 및 동작**
- 월을 주차 단위 블록으로 나눠 가로 한 줄 스트립으로 표시한다.
- 각 블록에 해당 주의 시작일과 식단 구성 여부를 표시한다.
- 구성 여부는 색상뿐 아니라 텍스트/도트/채움 같은 보조 표시로도 구분한다.
- 주차 선택 시 `PLAN-01`에서 선택한 주를 표시한다.
- 월의 첫/마지막 주 처리 및 주 시작 요일은 Q-05 정책 확정 후 적용한다.

## 6. 장보기 화면

### `SHOP-01` — 통합 장보기 목록

**목적**: 확정 식단에서 필요한 재료를 통합하고, 보유 여부와 구매 수량을 조정한 뒤 외부 구매 검색으로 연결한다.

**진입**: 홈 요약, 하단 `장보기` 탭, 식단 확정 완료 후.

**구성**
- 상단: 대상 주차, 확정 식단 연결 정보, 필요 시 `식단 보기` 액션.
- 재료별 목록 행:
  - 재료명
  - 통합 필요량과 단위
  - 사용자 편집 구매 수량과 단위
  - `보유함` 체크/토글
  - `사용 메뉴 보기` 액션
  - `대체 재료` 액션
  - `쿠팡에서 검색` 링크
- 구매 대상 재료를 빠르게 파악할 수 있도록 보유 여부와 구매량을 명확히 구분한다.

**동작 및 계산 규칙**
- 필요량과 구매 수량은 별도 값이다.
- 같은 정규화 재료명과 호환 가능한 단위만 합산한다. 단위 변환 규칙이 없으면 원문 단위를 유지하며 임의 환산하지 않는다.
- `보유함`은 구매 필요 집계에서 제외하고, 장기 재고 수량은 추적하지 않는다.
- 구매 수량은 목록에서 인라인으로 편집하고 변경 즉시 저장하는 방식을 제안한다. 입력 도중 취소가 필요하면 원래 값으로 복구할 수 있게 한다.
- 구매 그룹 기준(Q-09)이 확정되기 전에는 냉장/상온 또는 구매 시점별 임의 그룹을 만들지 않고 통합 목록을 사용한다.
- `구매 완료` 표시는 Q-09 확정 전까지 MVP에 포함하지 않는다.
- 쿠팡 검색은 현재 구매 대상 재료명으로 검색 URL을 구성해 새 탭에서 연다. 상품 정보 수집, 장바구니, 주문, 주문 금액 계산은 제공하지 않는다.

**상태 및 예외**
- 확정 식단이 없으면 장보기 목록 대신 식단 생성/확정 안내를 표시한다.
- 단위가 모호하거나 구매량 입력이 유효하지 않으면 저장을 막고 해당 행에 설명을 표시한다.
- 대체 적용/재계산 실패 시 목록 일부만 바뀌지 않도록 마지막 정상 상태를 유지하고 재시도를 제공한다.

### `SHOP-02` — 재료 사용 출처 상세

**형태**: 바텀시트. 장보기 목록 맥락을 유지하며 짧게 확인한다.

**진입**: `SHOP-01`의 `사용 메뉴 보기`.

**구성**
- 통합 재료명 및 통합 필요량.
- 해당 재료를 사용하는 날짜/레시피 목록.
- 각 출처의 원문 재료명, 레시피별 계산 사용량과 단위.
- 대체 재료가 적용된 경우 대상 레시피와 현재 구매 대상 재료 표시.

**동작**: 닫으면 `SHOP-01`의 같은 스크롤 위치로 돌아간다. 특정 레시피의 사용량만 대체할 때 다른 레시피의 사용량이 유지됨을 명확히 한다.

### `SHOP-03` — 대체 재료 선택

**형태**: 바텀시트 또는 전체 높이 시트. 후보 설명이 길면 전체 높이 시트를 사용한다.

**진입**: `SHOP-01`의 특정 재료에서 `대체 재료` 선택.

**구성**
- 대체할 기준 재료와 대상 레시피/날짜를 먼저 표시한다. 전역 재료 변경이 아님을 설명한다.
- 대체 후보 1~2개. 후보별로 다음 내용을 표시한다:
  - 재료명 및 필요량/대체 비율
  - 예상 맛 차이
  - 조리법/순서 변경 필요 여부
  - 주의사항 및 불확실성
- 각 후보에 `이 메뉴에 적용` 액션.

**동작 및 규칙**
- 정보가 부족하면 `확인 필요`로 표시하고 대체량을 추측해 저장하지 않는다.
- 사용자가 `이 메뉴에 적용`을 선택하면 해당 레시피의 재료 관계를 갱신하고 목록을 재집계한다. 추가 확인창 없이 한 번의 명시적 동작으로 완료하는 방식을 제안한다.
- 같은 재료를 사용하는 다른 레시피의 사용량은 유지한다.
- 조리 변경 안내는 원문 조리 순서와 분리해 `대체 시 조리 안내`로 표시한다.
- 성공 시 시트를 닫고 `SHOP-01`에 갱신된 구매 대상 재료와 수량을 보여준다. 실패 시 마지막 정상 상태를 유지하고 재시도를 제공한다.

## 7. 레시피 화면

### `RECIPE-01` — 레시피 보관함

**목적**: 저장 레시피를 다시 열고, 식단 생성에 사용할 수 있는 레시피를 관리한다.

**구성**
- 저장된 레시피 목록: 레시피명, 예상 조리 시간(있을 때), 주요 재료.
- `레시피 URL 저장` CTA.
- 레시피 선택 시 `COOK-01` 진입.
- 검색·정렬은 기능명세 F-10에 따라 제공하되, 카테고리/조리 시간/재료/주방 도구 필터는 P1 확장으로 둔다.

**상태**
- 저장 레시피가 없으면 빈 상태 설명과 `URL로 레시피 저장` CTA를 제공한다.
- 미확인 조리 시간 등은 임의 수치 대신 `미확인`으로 표시한다.

### `RECIPE-02` — 레시피 URL 입력

**목적**: 외부 레시피 URL을 받아 추출 작업을 시작한다.

**구성**
- URL 입력 필드.
- `가져오기` CTA.
- 허용되지 않은 URL 형식의 입력 오류.
- 처리 중 상태와 원본 URL 표시.

**동작**
- URL 형식/허용 프로토콜을 검증한 후 추출을 요청한다.
- 처리 중 중복 제출을 막는다.
- 추출 성공 시 `RECIPE-03`으로 이동한다.
- 본문 추출 또는 AI 처리 실패 시 원본 URL을 유지하고 재시도/직접 입력 경로를 제공한다.
- 저장된 URL과 중복이면 `DIALOG-02`를 표시한다.

### `RECIPE-03` — 레시피 추출 결과 검토·편집

**목적**: 자동 추출 결과를 사람이 확인·수정한 다음 저장한다. 이 화면은 추출 실패 시 수동 입력에도 재사용한다.

**구성**
- 상태 표시: `검토 필요`, `확인 필요`, `미확인`.
- 편집 필드: 레시피명, 기준 인분, 예상 조리 시간, 재료명/수량/단위, 조리 순서.
- 원본 URL 및 `원문 열기` 링크.
- CTA: `레시피 저장`, `다시 시도`.

**동작 및 규칙**
- 불확실하거나 빠진 필드는 `확인 필요`/`미확인`으로 드러내고 사용자가 수정할 수 있다.
- 필수 필드가 유효하지 않으면 저장을 비활성화하고 해당 필드에 이유를 표시한다.
- 조리 시간·인분·수량을 임의로 채우지 않는다.
- 저장 성공 시 `RECIPE-01`로 돌아오며 저장 완료를 알려준다.
- 외부 페이지 본문은 데이터로 취급하고, 그 안의 프롬프트형 문장을 시스템 지시로 실행하지 않는다.

## 8. 조리 및 기록 화면

### `COOK-01` — 레시피 상세·조리

**목적**: 실제 조리 중 필요한 정보에 집중하고, 기록 입력 없이 한 번의 동작으로 완료할 수 있게 한다.

**구성**
- 레시피명, 예상 조리 시간, 계획 인분.
- 재료 목록 및 계획 인분 기준 수량.
- 조리 순서.
- 곁들임 레시피(있는 경우 별도 섹션/링크).
- 원본 레시피 링크.
- 이전 평가/메모가 있으면 요약 또는 `이전 기록 보기`를 표시.
- 주요 하단 CTA: `요리 완료`.

**동작 및 규칙**
- 평가/메모 입력은 요리 중 강제하지 않는다.
- `요리 완료` 한 번의 동작으로 해당 식단 날짜의 메뉴 항목에 완료 상태와 완료 시각을 저장한다.
- 중복 클릭은 완료 로그를 중복 생성하지 않고 동일 완료 상태로 처리한다.
- 같은 레시피를 다른 날짜에 요리하면 별개의 이력으로 기록한다.
- 완료 후 `평가·메모 남기기`는 선택적으로 제공하며 건너뛰어도 완료 상태는 유지된다.

### `COOK-02` — 요리 평가·메모

**형태**: 간단한 바텀시트 또는 소형 독립 화면. 입력 길이가 길어지면 독립 화면으로 전환한다.

**구성**
- 연결된 레시피명과 요리 완료 이력.
- 선택적 별점 영역.
- 자유 메모 입력.
- `저장` 및 `나중에` 액션.
- 기존 기록 재방문 시 이전 평가/메모를 확인할 수 있는 목록 또는 요약.

**동작 및 미확정 사항**
- 평가/메모는 레시피 ID와 해당 요리 이력 ID에 연결한다.
- 평가 없이 닫아도 요리 완료 상태를 변경하지 않는다.
- 별점 범위와 개선 항목 체크리스트 여부는 Q-12 결정이 필요하다. 정책 확정 전에는 별점 범위를 UI/데이터 계약에 고정하지 않는다. 초기 입력은 자유 메모를 중심으로 제공한다.

## 9. 확인창 및 공통 피드백

확인창은 사용자가 최종 결정을 내리거나 선택지가 필요한 경우에만 사용한다. 단순 메뉴 변경, 보유 여부 토글, 요리 완료에 추가 확인 단계를 두지 않는다.

### `DIALOG-01` — 식단 확정 확인

- **열리는 조건**: `PLAN-03`에서 `식단 확정` 선택.
- **표시 내용**: 대상 주차와 선택된 요일 수, 확정 후 통합 장보기 목록이 생성된다는 안내.
- **버튼**: `확정하기` / `돌아가서 수정`.
- **확정 결과**: 식단을 `확정` 상태로 바꾸고 재료량을 계산하여 `SHOP-01` 목록을 생성한다.
- **취소 결과**: 기존 초안을 그대로 유지한다.

> 이 확인창은 여러 데이터와 장보기 목록을 생성하는 작업의 실수를 줄이기 위한 UX 제안이다. 사용성 테스트에서 단계가 과하다고 판단되면 `식단 확정` 버튼 한 번으로 확정되도록 간소화할 수 있다.

### `DIALOG-02` — 중복 레시피 안내

- **열리는 조건**: 동일 사용자가 동일 URL을 이미 저장한 것으로 확인됨.
- **표시 내용**: 기존 레시피명(가능한 경우)과 중복 저장 안내.
- **버튼**: `기존 레시피 열기` / `새 레시피로 저장` / `취소`.
- **규칙**: 기존 레시피를 자동 덮어쓰지 않는다.

### 화면 내부 오류/피드백 패턴

- **로딩**: `레시피 가져오는 중`, `식단 생성 중`, `대체 재료 적용 중`처럼 현재 작업을 명시한다. 중복 제출은 막는다.
- **오류**: 확인 가능한 원인과 다음 행동(재시도/직접 입력)을 보여준다. 원인을 모를 때는 임의 설명을 쓰지 않는다.
- **저장 성공**: 토스트 또는 인라인 상태를 사용한다.
- **부분 실패 방지**: 대체 재료 적용/목록 재계산 실패 시 레시피와 목록 중 한쪽만 변경된 상태를 남기지 않는다.
- **미저장 입력**: 레시피 편집 등 작성 중 내용이 있는 화면을 닫을 때 변경 사항이 사라질 수 있음을 안내하는 확인창을 추가할 수 있다. (보조 UX 제안)

## 10. 주요 사용자 흐름

### FLOW-01 — 레시피 저장 → 식단 생성 → 수정 → 확정

`HOME-01` 또는 `RECIPE-01` → `RECIPE-02` → `RECIPE-03` → `RECIPE-01` → `PLAN-02` → `PLAN-03` → (필요 시 `PLAN-04`) → `PLAN-03` → `DIALOG-01` → `PLAN-01` / `SHOP-01`

- 메뉴 변경은 선택 사항이다.
- URL 추출 실패 시 `RECIPE-02`/`RECIPE-03`에서 재시도 또는 수동 입력으로 복구한다.
- 기존 초안이 있을 때 새 생성 요청 실패가 기존 초안을 덮어쓰지 않는다.

### FLOW-02 — 장보기 → 보유 재료 제외 → 대체 재료 → 쿠팡 검색

`SHOP-01` → (필요 시 `SHOP-02`) → (필요 시 `SHOP-03`) → `SHOP-01` 갱신 → (필요 시 쿠팡 검색 새 탭)

- `보유함`과 구매 수량은 `SHOP-01`에서 바로 수정한다.
- 대체 적용 범위는 특정 레시피/메뉴에 한정한다.
- 구매 그룹 기준이 정해지기 전까지 별도 카테고리 그룹을 만들지 않는다.

### FLOW-03 — 오늘의 메뉴 → 조리 → 완료 → 선택적 기록

`HOME-01` → `COOK-01` → `요리 완료` → (선택) `COOK-02`

- 홈의 `필요 재료 확인` 및 `대체 재료 확인`은 기본 접힘 상태의 보조 영역이며, 대체 재료 선택 자체는 `SHOP-01`에서 시작한다.

- 기록하지 않고 나가도 완료 상태와 완료 시각은 저장된다.
- 이전 기록이 있다면 `COOK-01`에서 다시 확인할 수 있다.

### FLOW-04 — 주간/월간 식단 탐색 및 레시피 재탐색 (P1)

- 식단 탐색: `PLAN-01` ↔ `PLAN-05` → 날짜 메뉴 선택 → `COOK-01`.
- 레시피 탐색: `RECIPE-01` → 레시피 선택 → `COOK-01`.

## 13. MVP 범위 요약

**P0 — MVP**
- 홈과 기본 진입 구조
- 레시피 URL 입력, 추출 결과 검토/수정/저장 및 중복 안내
- 식단 생성 설정, 초안 검토, 날짜별 메뉴 변경, 식단 확정
- 통합 장보기 목록, 출처 상세, 인라인 구매 수량 수정, 보유 여부 표시
- 대체 재료 선택과 장보기 목록 동기화
- 쿠팡 검색 링크
- 오늘의 메뉴, 레시피 상세, 요리 완료 표시
- 선택적 자유 메모 저장을 위한 기본 구조

**P1 — 확장**
- 월간 주차 스트립
- 레시피 검색·정렬·카테고리·확장 필터
- 평가/메모 이력 탐색의 확장 UI

**범위 제외**
- 냉장고 재고 수량 및 재고 이력 관리
- 쿠팡 가격 수집, 상품 선택, 장바구니, 주문, 주문 금액 계산
- 사용자가 저장하지 않은 외부 레시피의 자동 추천
- 반응형 데스크톱 전용 레이아웃
