# Product Definition

**서비스 방향: 저장한 레시피를 실제 요리 일정과 장보기로 연결하는 주간 식단 계획 서비스**

- 레시피 아카이빙 기반 주간 식단 계획 서비스
- 저장 레시피 활용 식단 구성, 대체재 고려 통합 장보기 목록 생성, 요리 기록 저장

## 제품 설계 원칙

**원칙 1. 최소한의 입력으로 식단을 생성한다.**

사용자가 매주 같은 정보를 반복 입력하지 않도록 기본값을 제공한다.

- 평일 조리 시간: 30분
- 주말 조리 시간: 70분
- 기본 식사 인원: 1명
- 사용자는 요리할 날짜를 선택하고 필요한 조건만 변경한다.

**원칙 2. 자동 생성보다 수정 편의성을 보장한다.**

모든 추천 메뉴가 완벽할 수는 없으므로, 사용자가 원하는 날짜의 메뉴만 바꾸고 나머지 식단은 유지할 수 있어야 한다.

**원칙 3. 재료 관리는 사용자의 실제 행동을 방해하지 않는다.**

초기 버전에서는 냉장고 재고를 미리 등록하거나 지속적으로 업데이트하도록 요구하지 않는다. 사용자가 장보기 목록을 확인할 때 냉장고를 직접 살펴보고 구매 수량을 조정하도록 한다.

**원칙 4. 요리 중 추가 입력을 요구하지 않는다.**

요리 과정에서는 레시피 확인과 조리에 집중할 수 있도록 한다. 요리 완료 여부만 간단히 표시할 수 있고, 평가와 개선점 기록은 선택 사항으로 둔다.

**원칙 5. 식단 변경에 따른 정보를 자동으로 동기화한다.**

메뉴나 대체 재료를 변경하면 해당 레시피의 재료 정보와 통합 장보기 목록도 함께 업데이트한다. 사용자가 변경된 정보를 다시 계산할 필요가 없어야 한다.
